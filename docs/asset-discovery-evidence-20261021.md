## 查询条件如何配合

| 条件 | 本次实现中的作用 | Hunter 实际查询 |
| --- | --- | --- |
| 域名 | 已确认范围 + 实际发现记录；确认的根域可直接作为入口 | `domain=="host"` |
| 域名树 | 明确选择根域及其子域；包含排除子域时拒绝付费查询 | `(domain=="root"\|\|domain.suffix="root")` |
| CN / SAN | 与**同一张证书**的指纹绑定，核验名称是否位于确认范围；通配符不等于发现了具体主机 | 不额外追加 CN 查询 |
| Organization | 企业名称辅助信息，不能证明证书或资产归属 | 不因组织名自动付费查询 |
| SHA-256 | 精确关联同一张证书；必须存在当前项目来源，并且该证书名称全部位于确认范围且没有排除项 | `cert.sha-256="64hex"` |
| CNAME | 精确关联实际观察到的解析目标；范围外共享 CDN 不自动准入 | `cname_target=="target"` |

每次分页固定选择一种条件，不把 SHA-256、CNAME、CN 全部用 `&&` 叠加，也不把它们全部用 `||` 扩大查询。`&&` 是交集，可能漏掉只满足一种关系的资产；`||` 是并集，范围可能扩大，是否少收费不能在没有平台计费依据时保证。

同项目、同账户、同查询和同时间窗口复用分页记录。**不同 SHA-256 / CNAME 查询之间尚无语义覆盖去重**：即使入库合并为同一资产，平台仍可能对重复返回收费；本地去重不退积分。不得宣称已经消除所有重复计费。

SHA-256 是整张证书 DER 的摘要，不是企业标识、公钥摘要或“签名算法名称”。同域名续签会产生新指纹。目前固定近 30 天，Hunter 是否收录该证书以及收录时间都会影响命中。没有具体指纹和响应回执，不能把零结果直接归因于采集失败，也不自动扩大时间范围试付费请求。

## 本次修正

- 阻止“范围内主机携带其他企业证书”借用主机域名通过指纹准入。原始叶证书 / 最新 TLS 补采结果优先于历史服务商字段，禁止不同证书的指纹与名称拼接。
- 隔离区提供只读证书复核，保留页面规则、人工拒绝和回收站状态；命中只是复核线索，不自动解除隔离。
- 证书补采组件集中在任务中心，区分任务创建时范围、当前新任务范围、资产进度、唯一指纹和新增指纹。同证书部署在多台资产上只增加一个唯一指纹。
- 线索库新增域名批量排除：先预览，确认后对当前项目域名及子域、仅来自这些来源的证书线索做可恢复排除。独立来源仍引用的共享指纹保留。原始资产、证书、积分回执、历史不删除；以后重新提取也遵守排除规则。
- 服务端每页及恢复时复查证据和排除状态。已发出的请求无法撤销；不承诺退费。

## 错误日志

新构建中，账户验证和分页 HTTP 请求均写入应用数据目录 `diagnostics/hunter.jsonl`，通常为 `~/oviraptor/diagnostics/hunter.jsonl`。每 8 MiB 轮转，另保留上一份 `hunter.previous.jsonl`；超过保留上限前应复制需长期保存的诊断。

记录 UTC 时间、本地诊断编号、项目 / 查询编号、网络模式、无凭据接口路径、查询语法、日期范围、页码、条数、耗时、HTTP 状态、允许的响应头、Hunter 业务码 / 错误说明 / 语法提示、积分回执、响应字节数与摘要。连接失败保留脱敏底层错误链；非 JSON 仅记录解析错误与摘要，不保留完整 HTML。额外记录关联不符、无效 IP / 端口 / URL 等过滤计数和去重 / 入库数量。

不记录 Key、带 Key 的完整 URL、Cookie、账户姓名 / 手机 / 邮箱或完整网页。只读账户额度字段不包含 `personal_info`。日志文件权限为当前用户可读写；写不出开始日志时不发出请求。请求结果未知时禁止自动重发。

`direct` 仅忽略应用 / 环境代理，全局 / TUN VPN 仍可能接管流量。代码和本次测试不修改 VPN、系统代理、路由或 DNS。
