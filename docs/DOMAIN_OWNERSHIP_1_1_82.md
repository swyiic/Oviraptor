# 1.1.82 域名归属建议纠错

## 已确认的问题

真实项目中的 `essences.com.cn`、`grcbank.com` 被一组供应商证书元数据带入建议。原始 CN 为 `*.10086.cn`，但 `cert.domain` 是跨多个企业的关联列表；没有可解析的同叶证书。程序将这些名称扁平分组，并在相关性人工意见为 `accepted` 时放行全部根域。另一类问题是将 `gaxcy.cn` 下一个服务主机的未绑定 Organization 提示，提升为整个根域归属。

模型原有审阅接口只对本地摘要做分类，不提供联网搜索工具。这些结果不能称为已经查证企业归属。

## 修复后的边界

- 逐域记录实际字段、主机、单位与资产来源。`cert.domain` 保留为发现线索，不能当作已验证的 SAN，也不能继承 CN 所对应单位。
- DER 只绑定同叶证书实际 CN/SAN 与 Subject Organization；明确 ICP 只绑定相应端点。采集标签、Issuer、同 IP、CNAME 和模型理由不提供归属授权。
- 核对本轮目标与已确认组织目录；不从模型理由生成子公司关系。目录中没有的子公司关系继续待核验，不凭“移动”“中移”等字样推断。
- 人工“认可相关”不再绕过逐域核验。具体服务主机不会自动扩大成整个可注册根域。旧相关性意见、模型回执和原始数据均保留。
- 旧版缓存自动按新策略重新投影，不需要重新发起整轮模型请求。资产页与聊天只将带来源的合格建议加入一次确认名单。
- UI 展示实际核验来源，AI 推断单独标识；未核验数量汇总，不增加逐条人工审核。明确显示这是本地证据核验，本轮没有联网企业查证。

## 验证边界

回归覆盖跨企业关联列表污染、人工 accepted 与单项汇总的绕过路径、未绑定组织提示、服务主机和根域边界、目录目标不匹配、源事实变化及旧缓存升级。真实项目使用一致性备份只读复算，再从已安装 App 的认证服务核对新建议；不确认新增范围、不调用 Hunter、不修改 VPN。

本版本修复错误推荐与错误授权资格，并没有新增自动联网企业调查系统。缺少独立依据的候选不会因为模型的高置信度而变成“已核实”。

## 本轮实测结果

中国移动项目的一致性副本包含 98,989 条关联资产和 12,478 组已整理证据。只读复算耗时 6.04 秒（含测试进程启动）：截图的三个域名均不再进入可确认名单。原缓存 109 个家族的建议被新策略撤出；当前不存在足够依据可自动推荐的新增范围，202 个缺证家族、313 项未核验范围只汇总暂存，未新增人工待办。已确认范围仍为 `cmsrict.com`。

该项目当前没有确认过的组织目录、集团子公司关系或目标单位别名配置。模型此前给出的单位关系不能代替这些依据；本版本没有把缺少资料的结果解释为“这些域名一定不属于目标”。

原生资产回归 171 项通过，3 项需私有数据或外部条件的既有用例不计入自动验收。Host/SDK/应用回归 948 项通过、19 项既有平台跳过；完整 UI 基线 1,923 项通过，随后暂停/空候选场景的两组 SFC 回归 36 项通过（与完整基线重叠，不相加）。首次 Host 测试遇 macOS `/var` 与 `/private/var` 临时目录别名差异，使用规范化临时目录 `TMPDIR=/private/tmp` 后全部通过，未修改全局环境或应用权限。

修复不进行新增范围确认，不恢复隔离或回收资产，不调用 Hunter，也不会重新消耗原有 230 次模型审阅请求。
