# Hunter 精确关联、自动翻页与积分回执（2026-10-20）

本轮按用户最新要求，替代 ProbeFix8 的“免费积分、第一页最多10条”方案：允许使用免费和权益积分，不设积分预算；仅针对已核对的技术线索自动翻页，展示每页和累计消耗。没有增加模糊公司名查询，也不把关联命中直接认定为业务归属。

## 查询准入与关联核对

依据用户提供的官方帮助中心原文：证书 SHA-256 使用 `cert.sha-256="64位摘要"`，域名使用 `domain=="host"`，CNAME 使用 `cname_target=="target"`。明确确认的域名树可选择根域和子域条件。摘要格式校验和查询目标规范化不允许夹带查询表达式。

指纹/CNAME 必须在当前项目实际观察记录中存在，并能追溯到有效项目资产与已确认域名范围。证书使用者域名不再冒充单张证书的指纹。未知摘要、猜测子域名、其他项目线索、删除资产的唯一来源都会被拒绝。新增多来源证据表，避免同一摘要的首条来源被删除后，其他有效来源也一起失效。新 Hunter 结果入库后立即提取指纹 / CNAME 线索，不必等手动遍历历史资产，Agent 下一轮即可看到并继续规划。

结果再次核对返回的证书摘要、域名或 CNAME。缺少可核对字段或身份不合法的记录，保留原页、记录拒绝数量并暂停，不继续消耗积分去收集无法验证的结果。IP-only TLS 和非 Web 服务保留为候选，不用 ASN 过滤证书关联 IP。请求 `is_web=3`，覆盖 API 返回的全部资产类型。

## 自动翻页与恢复

- 冻结查询、账户摘要、日期范围和分页大小。当前日期范围仍是近30个日历日；界面直接展示起止日期，未扩展为全历史查询。
- 按 `page=1,2,3…` 继续读取报告的全部可用分页，没有第一页或固定十条总量截断。每页大小可在资产 API 设置中调整，受账户导出能力约束。
- 每次请求前持久保存发送意图，收到响应后先落盘，再进行积分记账和本地入库，最后推进游标。
- 超时/断线且结果未知：保留原页游标，标明可能扣费，不自动重发。收到页面后本地导入失败：恢复使用已保存页面和稳定的导入请求 ID，不重新购买该页。
- 暂停/退出后保留记录。恢复沿用原查询与分页大小，账户 Key 改变时拒绝将原游标接到另一个账户。同一 Key 的本应用分页任务串行执行，避免本应用并发请求混用进度。
- 提前空页、重复整页、分页限制、字段/权限错误、变化的总量或无法验证的记录都明确标为未完成。不能将“流程结束”当作“第三方实时索引绝对无遗漏”。

## 积分展示

按用户授权允许查询消耗账户可用积分；免费积分为0不再单独阻止权益积分可用的账户。额度耗尽或服务端拒绝后保存游标并暂停。实际使用哪类权益仍由 Hunter 服务端结算。

每页显示 `consume_quota`、`rest_quota`，累计记录已确认积分，账户仅投影免费/权益余额等非个人信息字段，不返回 Key、手机号、用户名。只有官方页面回执可以确认该查询消耗；其他客户端使用、充值和延迟扣费可能影响账户净变化，因此不把余额差冒充本查询的准确费用。缺失回执单独标为未知并暂停继续扣费。

本地去重不承诺退还平台对重复返回结果的扣费。多个精确条件仍可能命中相同资产；主表按生产端点身份合并，同时独立保留证书/域名/CNAME 关系证据。

## UI

查询页新增证书 SHA-256、精确域名、已确认域名树和精确 CNAME 选择。蓝色按钮启动精确关联自动翻页，红色按钮暂停，恢复按钮使用原游标。自主探测可启用 Hunter，界面明确告知允许使用全部可用积分、不设积分预算。

进度面板显示时间范围、查询语句、累计返回数量、去重后的数量、平台总量、下一页、已确认消耗与未知部分、免费/权益余额和未完成原因。最近20页回执是显示窗口，所有已收到的页仍保留在本地；查询列表显示最近30个查询。
