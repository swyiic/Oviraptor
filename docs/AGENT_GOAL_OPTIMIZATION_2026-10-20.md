# 聊天导航与 Agent 调试记录

本次范围：左侧会话导航、输入框下方的模型与权限、真实模型协议兼容、只读查询与失败恢复。不是整套自主探测能力的最终验收。

## 已修改

- 左侧统一显示新对话、搜索、最近对话、删除入口；移除顶部重复会话下拉框及新增/删除按钮。模型与权限放到输入框下方。
- 权限面板区分当前会话文件权限与项目应用权限。查询结果按项目、会话及运行时身份隔离，过期异步响应不会串到新会话。
- 提供商侧工具名称使用合法、确定的别名，内部仍回到原始 MCP 名称并经过原有权限校验。DeepSeek 思考模式使用 auto 工具选择，续传私有 reasoning_content，不向 UI 发布。
- 单步项目读取仅提供适用的数据读取工具，避免模型把计数问题转成任务条件修改循环。当前追问优先于历史目标；目标归属/扫描许可字段不再被解释为需要重复授予库存读取权限。
- 相同工具和参数失败两次后停止第三次执行，并明确本轮缺口；允许换适用的读取工具恢复。
- 验收条件按文件存在、文件内容、历史读取字段、独立重读字段四种 schema 明确各自必填字段，避免模型混填；文件位置明确使用工作区相对路径，任务版本冲突返回重新读取当前版本的指引。

接口依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)及[Chat Completion 契约](https://api-docs.deepseek.com/api/create-chat-completion/)。修改前实际请求出现工具名称非法与 thinking/tool_choice 冲突两个 HTTP 400；修改后本轮场景均收到 HTTP 200。

真实模型场景：项目计数、证书指纹追问、精确域名空结果、注入读取失败后恢复、查询后的 CNAME 概念问答、另一个项目的空库存隔离。使用 `tools/run_agent_quality_eval.mjs --source-host <现有 Host 目录> --output <私有报告路径>` 显式启动；只读取指定配置，凭证仅进入私有临时 Host，结束后删除临时状态，不写入报告。

多步场景使用同一命令追加 `--suite workflow`：读取真实临时库存并保存 summary.json；追问只改 scope 并保留两项计数；关闭并重新建立 Host（包含 SQLite、应用 worker 与新模型会话），根据已保存聊天继续修改原文件。外部检查器直接解析文件，检查写入后确实调用读取、任务处于 completed、存在成功的 Host 有限验收凭据。意外授权请求会被测试器拒绝并判定失败，不会无限等待或批准额外权限。

调试前，前两个多步场景虽最终完成，但出现 4 次验收/版本参数错误；本轮 schema/错误指引修复后，前两个场景未出现参数错误。重启后的第三个场景出现一次任务版本冲突，通过重新读取任务版本自行恢复。单次真实模型结果不证明稳定的延迟或成功率，未据此放宽权限或验收。

原生验证通过自带隔离环境的临时启动器进行：数据目录为 `/private/tmp/oviraptor-acceptance-agent-goal-*`，验证前检查目录归属及 0700 权限。交付 App 不含该启动器、测试数据库或凭证。未替换 `/Applications/Oviraptor.app`，未更改 VPN/代理路由，未对用户数据库/CAS 做测试写入。

## 后续验证

已验证的是上述有限场景。真实目标上的长期自主探测、数万资产的长时间性能、全部提供商、Hunter 线上采集与额度扣费并未在本轮验收；本轮未调用 Hunter，不消耗其积分。模型回复仍存在冗长和内部字段过多的问题，提示改进不能保证每次措辞一致。

旧 Host 中已安装的 Assets 应用不会被覆盖式改写。本轮仅以只读查询核实本机 Host 中仍是 Assets 1.0.0；交付包携带 1.1.0。使用本地新版工具需要在配置中心更新内置组件，验证时未自动修改该真实 Host。版本或运行时身份变化需要一次新的对应授权，之后同一范围应复用，不应每轮重复请求。
