# 聊天导航与 Agent 调试记录

本次范围：左侧会话导航、输入框下方的模型与权限、真实模型协议兼容、只读查询与失败恢复。不是整套自主探测能力的最终验收。

## 已修改

- 左侧统一显示新对话、搜索、最近对话、删除入口；移除顶部重复会话下拉框及新增/删除按钮。模型与权限放到输入框下方。
- 权限面板区分当前会话文件权限与项目应用权限。查询结果按项目、会话及运行时身份隔离，过期异步响应不会串到新会话。
- 提供商侧工具名称使用合法、确定的别名，内部仍回到原始 MCP 名称并经过原有权限校验。DeepSeek 思考模式使用 auto 工具选择，续传私有 reasoning_content，不向 UI 发布。
- 单步项目读取仅提供适用的数据读取工具，避免模型把计数问题转成任务条件修改循环。当前追问优先于历史目标；目标归属/扫描许可字段不再被解释为需要重复授予库存读取权限。
- 相同工具和参数失败两次后停止第三次执行，并明确本轮缺口；允许换适用的读取工具恢复。
- 验收条件按文件存在、文件内容、历史读取字段、独立重读字段四种 schema 明确各自必填字段，避免模型混填；文件位置明确使用工作区相对路径，任务版本冲突返回重新读取当前版本的指引。

接口依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)及[Chat Completion 契约](https://api-docs.deepseek.com/api/create-chat-completion/)。修改前实际请求出现工具名称非法与 thinking/tool_choice 冲突两个 HTTP 400；修改后本轮场景均收到 HTTP 200。

## 真实项目复测后的补充修复（AgentFix16）

上一次真实项目查询暴露了尚未通过的场景：问“已保存的证书 SHA-256 去重数量”时，“保存”被当作写入指令，单步读取进入任务计划/验收循环，最终以 `max_turn_requests` 中断。这说明前面的有限场景不能推导为任意措辞可用。

本轮改动：

- 把“已保存/已采集”等历史记录描述与实际保存、修改、删除、补采命令分开；简单项目读取不注入任务计划 DSL。
- 无筛选的库存计数先只提供统计工具，成功后进入直接回答阶段；失败仍允许使用其他适用只读工具恢复。域名、端口、状态码、来源及分组等条件查询保持正常读取流程，不用总库存替代筛选结果。
- 在 Assets 所有的同步代码中补充项目证书覆盖统计：HTTPS 记录、名称/序列号记录、已存指纹、原文候选、缺少已存证书的 HTTPS 记录。原文候选仅按字段存在性统计，不冒充解析验证；统计不包含完整证书字节、不推断归属或 TLS 信任。缺字段旧库报告不可用，而不是编造零值。
- 向 Agent 说明本地提取不联网、名称/序列号无法还原指纹；没有当前可用执行工具时不得声称已经补采。

验证：Host 527 通过、17 跳过、0 失败；包括失败读取替代路径、带条件计数、非法/缺失证书字段、跨项目和回收资产隔离。真实原生 App 使用原会话和原模型重放上述中断问题，正常完成；再追问实际证书缺口，正常完成。两轮各只调用一次库存统计，未重复授权。真实数据、工具记录、耗时和截图只留在本地私有备份，不随源码上传。单次结果不构成长期稳定性或完整自主探测验收。

### 尚待接通的执行能力

目前 Assets 应用发布的是库存读取、导入及 insight 工具，并未发布聊天可调用的证书批量补采工具。原生资产页复测与聊天 Host 不是同一条执行入口。应按下面顺序继续，而不能用提示词假装能力已存在：

1. 把证书补采接成持久任务：明确当前项目与批准范围、缺失资产集合、SNI/端口、并发和超时，按资产保存成功/失败/跳过原因，支持暂停和重启续跑；完成证据必须是实际 DER 和入库后的指纹。
2. 为聊天 Host 发布适用的任务创建/状态/暂停工具，复用现有权限与项目绑定，让 Agent 能创建任务并读取实际状态。批量网络请求由任务执行器处理，避免每条资产消耗一次模型轮次。
3. 将任务进度区分为本地提取、TLS 补采、付费关联查询，显示待处理/完成/失败/新增唯一指纹；旧任务的验收状态与当前简单问答应清楚区分。
4. 用真实项目验证暂停、重启恢复、失败有限重试、筛选范围和来源字段保留，再验证精确线索驱动的 Hunter 查询。未接通之前，不把本轮计数/解释修复称为自主执行能力完成。
