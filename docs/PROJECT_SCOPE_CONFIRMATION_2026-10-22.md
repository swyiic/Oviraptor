# 全项目种子与一次范围确认（1.1.78）

## 修复的问题

旧按钮仅从当前页挑选候选，人工已认可项及其他页被漏掉；结果提示及确认框位于长列表下方。确认只保存范围，没有启动自动补证。旧记录还用 `ambiguousIdentity` 同时表示“未绑定真实指纹”和“跨域证书”，使 10086.cn 等同域候选被错误挡住。

现在新增 `seed_review_scope_proposal`：读取当前项目完整审阅快照，复用已有 AI 回执和人工认可，按 PSL 可注册域汇总证书、名称、资产及缺证记录。单张证书的“选择并汇总同域证书”同样跨所有页关联，不受搜索或队列筛选影响。建议及其证据立即显示在列表上方，明确展示父域及其子域授权。

普通域名可一次确认根域家族；共享平台（含项目已配置的共享域名）仅建议实际观察到的具体主机，不因一家租户证书而授权整个平台。人工排除、域名排除、证据截断、模型技术错误不作为自动新增范围的依据。人工明确认可的多域名称可作为范围建议，但仍须本次范围确认。

新增 `confirm_seed_review_proposal`：核对全项目证据/审核版本和旧范围，重新检查当前非回收资产上的实际名称依据，事务保存所选范围及其相关名称。成功后启动共享补证任务；启动失败会明确显示“范围已保存，补证未启动”，可以单独重新启动，无需重复确认。旧范围任务保留记录，新范围任务接续执行。

补证先分页读取整个项目的本地证书，再执行网络队列：IP 地址不在目标域名内，也能从其证书 SAN/CN 提取范围内名称，覆盖后续页及审阅卡片预览之外的证书名称。只把已确认范围内的名称送入 CT、DNS/CNAME、TLS，外部名称不自动探测。本地批次统一关联审阅证据，避免每条资产都重复写整个队列。新增范围内的旧缺证投影可自动归为已处理；原模型回执、人工决定和隔离/回收状态保留。

新项目流程改为：1 采集初始资产 → 2 全项目 AI 提炼与范围确认 → 3 范围内主动探测。已有本地资产可直接进入第二步，无需重新消耗测绘额度。

## 费用和边界

范围汇总仅使用已有本地模型结果，不发送新模型请求，不调用 Hunter。确认后的免费补证沿用持久队列、暂停/恢复、重试及错误日志。Hunter 的真实叶证书指纹、同证书域名、共享目标和当次范围校验保持独立，没有因名称关联而放宽付费准入。

未知名称可能属于第三方，不能为了减少待补证数字自动授权。确认域名家族后，相应名称和证书自动处理；真正的身份不一致单独汇总。无法仅凭现有名称确认的项目仍暂存，不要求人工逐条审核。CT/DNS 的网络错误仍记录并退避重试，不等于资产不存在。
