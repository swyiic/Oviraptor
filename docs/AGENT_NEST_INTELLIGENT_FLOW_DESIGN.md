# Agent × Nest 智能化流程设计

> 目标:让扫描"聪明",但不要把 LLM 塞进每一步的同步热路径。本文给出分工原则、具体时序、控制面与护栏、以及对接现有代码的落地阶段。

## 0. 先承认原设想的问题

原设想:**创建任务 → 每个阶段结果发给 agent → agent 决定下一步 → Nest 据此推进(同步闭环)**。

它为什么"甚至不如通用 agent":

1. **LLM 进了热路径**:每个目标、每个阶段都等一次模型往返 → 慢、贵、不稳;一个 500 目标的扫描要几千次模型调用。
2. **丢掉内核的长处**:Nest 本来能并行跑很多目标、有预算、有确定性侦察与有界验证。让 agent 逐步决策,这些全废了,退化成"一个会调扫描工具的慢 agent"。
3. **把确定性问题交给了概率模型**:爬取、指纹、抓 API、跑探针、去重、存证据——这些是机械活,交给模型只会更慢更飘。

结论:**不是让 agent 做得更多,而是让它只做"判断真正有价值"的那几步。**

## 1. 正确的分工

### 1.1 确定性内核(Nest 干,不碰 LLM)
爬取 / 侦察 / 指纹 / **真实浏览器运行时采集** / API 发现 / 有界验证探针 / 去重 / 证据存储 / 预算 / 跨目标并行。
这些要快、要并行、要可复现。

### 1.2 LLM 的三个角色(都在热路径之外)
- **策略师(前 / 批量 triage)**:拿到一批目标的侦察证据,判断**哪些值得深挖、用什么策略**。这正是你那两个目标死掉的地方——内核用"静态 0 分就跳过"的死规则,而策略师会看到"这是个 BI 仪表盘 / 移动资产,静态看不到不代表没价值,升级到运行时采集或带认证再看"。
- **监督者(中 / 异步事件回路)**:对 Nest 的阶段事件做反应,发**有界的纠正指令**:升级/降级某目标、补一个假设、改验证策略、叫停、转人工。**不是替内核决策,而是给内核喂参数。**
- **分析师(后 / 合成)**:把原始证据变成带严重度和复现步骤的发现与报告。

> 口诀:**内核做工,LLM 掌舵;LLM 不在每一步里,只在岔路口。**

## 2. 具体流程(时序)

```
创建任务
  │
  ├─[内核] 并行侦察每个目标(含真实浏览器采集)──→ 结构化证据(valueScore/surface/apis/opportunities/hypotheses…)
  │
  ├─[LLM·策略师] 批量 triage:读证据,给每个目标定「调查层级 + 策略 + 初始假设」
  │        （一次调用覆盖一批目标,而不是每目标一次热路径往返）
  │
  ├─[内核] 按层级并行执行有界调查(标准/深度),边跑边发阶段事件
  │            │
  │            └─[LLM·监督者] 只在"有意义的事件"上被唤醒(默认门控+熔断):
  │                   • 这个探针出了新证据 → 要不要顺藤摸瓜(加假设/升级)
  │                   • 这个目标卡住/零增益 → 升级(认证/影子API/旧版本)还是收尾
  │                   • 预算快到 → 把预算往高价值目标倾斜
  │                   发出的是「有界指令」,内核把它当输入消费
  │
  └─[LLM·分析师] 全部收敛后:按证据合成发现 + 报告 + 人工复核清单
```

关键:**策略师是批量的,监督者是事件驱动+门控的**,都不是"每步必问"。绝大多数目标内核自己就跑完了,LLM 只在拿不准或有新线索时介入。

## 3. 内核要暴露的"控制面"(agent 能掌舵的旋钮)

这些 Nest 已经有了,只是现在由内核自己定、没开放给 agent:

| 旋钮 | 现状 | 开放后 agent 能做 |
|---|---|---|
| 调查层级 `automationTier`(recon_only/standard/deep) | 内核按 valueScore 定 | 按资产价值与证据升级/降级 |
| `scanMode`(skip/manual_review/investigate) | 低分即 skip | **改成"升级阶梯",见 §5.1** |
| 升级开关:运行时采集 / 认证采集 / 深爬 | 内核默认 | 对低静态信号的高价值目标主动开 |
| 假设/机会队列 hypotheses/opportunities | 内核生成 | 追加 agent 提出的定向假设 |
| 验证合同 `verificationPlan` / `requiredBaselineFamilies` | 固定 | 按目标裁剪要测的族 |
| 预算(每层 token/请求上限) | 配置固定 | 在总预算内按价值重分配 |
| 执行控制:pause/cancel/supplement | 已有(task_binding) | 叫停、补投、定向纠正 |

好消息:**投递这些指令的管道本会话早先已经搭好了**(实时事件管道 A + 门控反应 B + task_binding 的 directive/supplement/execution-control)。缺的是:①内核把这些当"决策输入"消费,②一个真正的监督策略(而不是只读分析)。

## 4. 护栏(让"自动掌舵"安全)

- **预算**:每层 token/请求硬上限;agent 只能在总预算内**重分配**,不能凭空扩预算。
- **写作用域**:agent 的指令只限一组预授权的安全动作(升级层级、加假设、调验证、pause、supplement),**不含**扩大扫描范围/碰新目标/越权。
- **幂等 + 在途感知**:同一 `(目标, 纠正意图)` 不重复下达;读 `pendingCommands` 避免和在途指令打架。
- **熔断**(B1 账本已实现):每 attempt 反应次数上限 + 短时爆发熔断,断掉"agent↔内核互相刺激"的回授环。
- **人工门**:高风险或超预算的升级 → 默认转人工确认,而不是自动执行。
- **默认只读起步**:先让监督者"只建议不自动写",人确认有价值后再逐步放开有界自动写。

## 5. 落地阶段(先修地板,再盖楼)

### 5.1 阶段一:修好确定性地板(没有它,agent 没东西可分析)
1. **修真实浏览器采集**:当前现代 SPA 的运行时采集没执行(`browser_network_broker_unavailable`),导致 SPA 一律 0 分。这是你"产生不了东西"的直接原因,必须先修。
2. **把"跳过门禁"改成"升级阶梯"**:静态低信号 ≠ 不值得查。改为
   `静态 → 运行时采集 → 带认证采集 → (策略师裁决) → 才可能 recon_only`,
   且永远是"保留并标注待复核",不是"消失"。
   → 光这两步,就能让你那种 BI/SPA 目标真正进入调查、产出证据。

### 5.2 阶段二:策略师(批量 triage)
侦察完成后,一次调用把一批目标的证据喂给模型,产出每个目标的「层级+策略+初始假设」,写回内核的控制面。低频、批量、便宜。

### 5.3 阶段三:监督者(事件驱动纠正)
接上 A/B 管道:新阶段事件 → 门控判定该不该反应 → 反应一回合 → 产出有界指令 → 内核消费。默认只读建议,再放开有界写。

### 5.4 阶段四:分析师(合成)
收敛后把证据合成发现+报告+人工复核清单(内核已有 manualDeepDive/coverage-gap 结构,拿来即用)。

## 6. 为什么这个不比通用 agent 差,反而强

- **快且省**:LLM 调用从"每步每目标"降到"每批一次 + 少数岔路口",成本和时延降一两个数量级。
- **可并行**:内核照样一次跑几百目标,LLM 不再是瓶颈。
- **确定性 + 智能兼得**:机械活确定性复现,判断活才上模型。
- **安全可控**:预算/作用域/熔断/人工门,无人值守也不会失控。
- **真正"智能"的地方被放大**:triage 优先级、假设生成、升级判断、结果解读、报告——这些才是模型比死规则强的地方。

## 7. 一句话收束

把 Nest 当成一支能自己干活的队伍,**agent 是教练不是提线木偶**:开场布置战术(策略师)、场上关键球喊话(监督者)、赛后复盘(分析师)。队伍该怎么跑还是自己跑。这样才既聪明又不垮。
