# 1.1.89 资产发现与 Agent 流程整理

资产组件版本：1.2.11。已有配置、权限、资产、隔离记录及查询历史沿用。

## 正常使用路径

1. 打开项目的“发现资产”，输入目标单位或业务。新项目先由 FOFA 采集；已有数据的项目沿用本地证据，默认增量处理。
2. 点击一次开始。整理、核验、免费补证与后续阶段由后台任务接续，无需逐批点击提取，也无需逐张证书触发探测。
3. 有新增范围时，按域名家族汇总确认一次。共享平台保留具体租户主机边界。已确认范围继续自动处理；暂缺证据的记录自动保留，真正的身份冲突单独集中展示。
4. 到资产列表查看合并结果，到“项目种子”查看证书、域名、CNAME 的来源、发现轮次和关联记录。导出相关列放在最右侧。

首次采集、增量发现和自动补证共用主入口。手动单条补查、独立 Agent 探测、补证并发等选项保留在高级工具中，不需要在正常流程中逐项配置。

## 本轮实际修复

| 问题 | 修复后的行为 |
|---|---|
| 补证进入 `waiting_storage` 后不再刷新，容易被误认为需要重新启动 | 显示等待本地存储，继续跟踪原任务；不创建新任务 |
| 较早的状态响应覆盖刚完成的开始、暂停或冲突处理结果 | 操作开始时废弃旧读取，迟到的结果和错误不再回写 |
| 多个刷新入口同时读取同一项目状态 | 共用正在执行的一组读取，减少重复 IPC 和数据库工作 |
| 隐藏页面持续轮询 | 隐藏时停止页面轮询，重新显示时读取一次；后台采集与补证不受影响 |
| Hunter 账户状态缺失时被视为可用 | 未读到明确配置状态时关闭付费入口，免费发现可继续；不会提示误改已有 Key |
| 确认范围或审核后，在回读状态时切换项目 | 旧项目的成功提示与确认事件不会发布到新项目 |
| 状态返回异常导致加载不结束 | 保留上次有效结果，结束加载并显示可重试状态；读取未恢复前不提交新操作 |
| 操作失败后，成功的状态回读立刻擦掉错误 | 分开显示操作错误与读取错误，保留操作原因；状态核对不自动重放该操作 |
| 归档页面仍可能显示可操作的高级补证控件 | 历史可读，阻止启动、恢复及冲突处理操作 |

## 准确性和费用

- AI 建议、资产来源、证书相同和 CNAME 关系分别保留为证据。候选范围仍需要逐域绑定依据；普通关联关系不能代替归属确认。
- 新增授权范围由用户确认。完全放开工具权限不等于允许系统自行扩大目标范围。
- Hunter 除了显式授权，还检查实际种子来源、证书/域名/CNAME 条件、账户配置和既有回执状态。配置已保存不表示当前网络可连通。
- Hunter 按精确条件翻页，保留每页与累计积分。结果或扣费未知时不自动重发；本地去重不能撤销平台已经收取的积分。
- 免费 CT、DNS、TLS 和模型调用是不同环节。免费补证不消耗 Hunter 搜索积分；AI 分析仍按当前模型服务计费。
- 缺少证据不等于无关，证书名称不代表主机当前存活，历史观察数量或人工样本认可率不作为 AI 总体准确率。

## 自动检查与验证边界

`npm test` 覆盖完整 UI、Host、SDK 与应用回归。Agent 测试入口为测试子进程解析临时目录真实路径，保留生产目录与符号链接防护。

CI 同时执行 Linux 和 macOS 的完整 Agent/SDK/应用测试，macOS 另执行构建证据检查。平台专属测试由对应作业覆盖，不能将各作业的 skip 数相加视为未覆盖数量。

原生回归包含资产发现、证书补采、终态持久化、任务恢复和证书解析。真实项目的范围核验、证据分流、种子历史检查使用一致性快照与独立副本。真实配置和原数据库不用于破坏性测试。

本地 TLS/HTTP 测试验证握手、队列与恢复实现；它不能代替真实目标当前可达性或外部平台数据完整性。Hunter 线上搜索与计费仍需要可访问它的网络。本轮保持 VPN 配置不变，不因联网失败修改账户或 Key。
