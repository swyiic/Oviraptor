# 聊天与配置中心统一权限（1.1.70）

旧配置中心仅保存应用权限，文件权限按单个会话保存，CLI/ACP 又独立询问。配置中心全选并不包含会话文件，因此出现“已经全开，换对话仍反复授权”。同一提供商的模型切换还会无条件更新 runtime identity，使已保存授权失效。

现在配置中心「数据权限」与聊天输入框下使用同一个工作空间权限模式：

- **每次询问**：未授权的操作执行前询问，已有精细应用授权继续生效；原有的会话文件授权仍可查看和清除。
- **完全放开**：一次保存，对本工作空间的新旧对话生效并跨重启保留；自动允许选择时已启用的应用权限类别，以及项目会话工作区内文件读写。原有精细授权独立保留，切回询问后恢复使用。运行时允许单次确认的请求自动使用 allow-once，避免写入不可撤销的 CLI 永久许可。

完整模式不会启用被禁用的应用，也不会自动包含未来新应用或新增权限类别；不扩大域名/资产范围，不绕过积分、工具预算、路径限制或未实现的能力。文件读写仍限于现有工作区，未接通的脚本执行不会凭权限开关变成可用功能。新增接收方需重新选择权限；同一认证提供商仅切换模型时复用授权。模型或工具不能通过 MCP 修改这一操作者设置。

后端以项目、接收方身份和版本校验保存。完整模式通过有效权限覆盖读取能力，不改写原有精细授权；每次异步工具调用仍携带策略版本见证，撤回权限后不重放已接受的操作。已显示的授权请求在用户选择完整模式后按精确 request/run 范围继续，界面同步关闭；其他工作空间不受影响。
