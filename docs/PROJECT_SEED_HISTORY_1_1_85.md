# 项目种子与增量发现 · 1.1.85

新项目先采集，已有项目复用现有数据。FOFA → 本地证据核验与 AI 提炼 → 确认新增范围 → CT / DNS / TLS 免费补证 → 已允许的 Hunter 精确查询 → 合并去重 → 新证据增量分析。AI 建议不替代独立归属证据；缺证自动暂存，真正的身份冲突集中审核。

## 使用入口

“资产 → 项目种子”展示本项目域名、证书 SHA-256、CNAME，以及来源、独立核验状态、首次/最近出现轮次、关联资产和查询历史。页面首次打开只整理本地派生索引；不启动模型或外部查询，不改配置、范围或资产。

“新建查询 → 继续增量发现”沿用已有任务。已有种子不因刷新重复出现；同一资产新增证书、备案主体或其他真实证据时重新分析。FOFA 重采和 Hunter 回流都能处理资产 ID 不变的更新。标签和完全重复导入不会增加 AI 工作。

## 历史与轮次

- 相同类型、值和通配属性合并为一个种子，来源与观察事件分别保留。项目之间互相隔离。
- 一轮可以有多个 Hunter 查询及多页结果。暂停、重启、继续原任务不增加轮次；新证据开启下一波，目标切换保留旧轮次。
- 新查询和晚到分页保留原轮次。详细历史可分页读取，展示来源引用、资产编号、查询条件、原查询 ID、页码和费用回执状态。
- 升级前的数据标记为历史基线，首次轮次与首次时间未知，不用索引生成时间冒充最初发现时间。新事件才记录实际轮次。
- 费用未知不显示为零；同一页不同状态的费用回执不可相加当作多次扣费。

## 可信程度

页面区分独立证据已核验、自动待补证、证据冲突和已排除。出现次数、AI 分数、人工认可样本率都不能等同于整个项目的资产归属准确率。无审查样本时不编造准确率。

当前目标绑定的证书 Subject、具体名称、备案及已核实的官方域名才作为核验证据。共享证书、范围外名称或仅有历史组织标签不自动获得 Hunter 查询资格。实际付费执行仍逐项、逐页检查最新来源、排除规则和已确认范围；种子页缓存不授予执行权限。

资产证据、组织目标、人工结论或规则变化会使派生核验结果失效；时间相关证明定期失效。只读页面保守展示待复核，后台分批重验，不靠轮询重复跑全库或模型。
