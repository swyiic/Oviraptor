# Web 补证准备入口与草稿原子性审计（2026-09-26）

## 结论与边界

本增量修复 Stage 9 补证工作流的一个实际前置缺口：工作台可以保存一个绑定本任务新身份的 Web 草稿，进入任务中心登记授权控制组，再由用户明确启动。不再只有“创建后立即启动”这一条工作台路径。

**不代表 EvidenceGap 全闭环已经完成。** 本轮没有实现从聊天中已封存的 proposal/assessment 一键生成关联任务，没有新增跨任务证据来源关系，也没有实现后续新证据回传、生成新 revision 和再次独立 Reviewer 审核。不能把草稿入口视为这些能力的替代品。

当前执行面仍为 `web_only`。未启用主机执行，没有移除授权/预算/证据硬边界，没有访问用户提供的外部目标。本轮使用临时本地数据库、实际 Vue SFC 测试与本地浏览器回环验证；不是桌面应用真实用户操作或授权目标端到端验收。

## 发现的问题

1. `AgentWorkbench.start()` 创建草稿后立即调用 `confirmSentinelScan`；授权控制组表单只存在于任务中心的 Web 草稿预览。工作台无法直接停留在可登记控制组的状态。
2. `create_sentinel_url_scan` 原先依次写任务、策略、登录身份归属和目标。策略校验、后续目标写入等失败可能留下半成品，或提前消耗尚需重试的任务草稿登录身份。
3. 原先熔断状态查询失败被当成“不在熔断区”，数据库读取错误可能放行目标。
4. 原先任务启动失败后，工作台仍保留已经绑定到新任务的身份和原始输入，易使用户将“启动失败”误解成“创建失败”。

## 后端变更

`src-tauri/src/commands/scan_lifecycle.rs`：

- 对外 IPC 参数保持兼容；提取真实生产路径使用的 `create_sentinel_url_scan_in`，便于使用真实 SQLite 直接验收。
- 使用 `IMMEDIATE` 事务覆盖项目状态、草稿身份验证、熔断查询、任务/策略/身份/所有目标写入与结果读取。提交失败返回错误；其他失败自动回滚。
- 检查任务、策略、每个目标的写入行数；SQLite `RAISE(IGNORE)` 不能伪装成功。
- 继续使用原有任务作用域校验和原有登录身份绑定函数。两个并发创建者争用相同身份时，只允许一个成功。
- 熔断查询失败不再默认放行。
- 拒绝 NaN、无穷大以及原有范围外预算。
- 不生成运行 attempt、Agent run、capability 或目标请求。
- 不改变旧 JSON 策略格式；身份材料不复制到其他任务。

本轮事务保证只覆盖这个 **Web URL 创建入口**；不能据此声称资产批量创建、代码任务创建或后续启动流程全部已经事务化。

## 前端变更与使用方法

工作台 Web 模式提供两个明确动作：

1. **保存草稿 / 配置控制组**：创建并保存任务，不调用启动接口；任务中心展示草稿、已登记目标和原有控制组表单。
2. **启动扫描**：保留既有的创建后明确启动方式，不强制所有 Web 调查都必须有双身份控制组。

需要授权对照验证时，应先在当前工作台捕获至少两个独立的新登录身份，再保存草稿，登记具体的 owner/tester 对象控制组，最后点击任务中心“确认并启动扫描”。匿名/单身份草稿不会被伪装为具备双身份对照前置条件。

`AgentWorkbench.vue`：

- 在处理函数入口阻止并发重复点击，而不只依赖按钮 disabled。
- 草稿创建成功即清除已被绑定的身份句柄并更换草稿作用域；启动失败不再让这些句柄作为未绑定身份继续使用。
- 启动响应失败会明确提示已保存的任务编号、要求核对状态，并转到任务中心刷新状态；不自动重试启动或再次创建。
- 工作空间/模式切换（包括 A→B→A）及卸载后，不从迟到的创建响应自动启动或抢占页面。
- 迟到的身份列表/登录完成事件不能把上一份草稿的身份重新塞回新草稿。

`SentinelBoard.vue`：

- 新 `prepareScan` 事件进入任务中心，不进入空结果页，不调用确认接口。
- 按返回任务的项目加载任务与目标，保留已创建任务标识；刷新后展示后端状态，包括启动结果不确定时已经变成运行态的任务。
- 刷新期间若用户已切换页面或预览另一任务，不强制打开原任务预览。

注意：若创建本身已经提交但 IPC 的创建响应丢失，本轮尚未实现创建请求的持久化幂等键/回执查询。也没有证明整个任务中心的异步加载竞争全部解决。后续不能用本轮的双击保护冒充跨进程幂等或全局异步一致性。

## 自动化验收覆盖

新增 `src-tauri/src/commands/tests_web_draft.rs`，共 5 个测试函数：

1. 真实生产创建函数 → 两个独立身份归属 → 读取控制组设置 → 保存真实控制组；验证任务仍是 draft、2 个目标、1 个控制组、0 个 attempt、0 个 Agent run；重复占用原身份失败且状态不变。
2. 任务写入、策略写入、第二个身份绑定、第二个目标写入分别注入 `ABORT` 和 `IGNORE`，共 8 组故障；每次比较任务/策略/目标/attempt/run/控制组计数及身份归属、作用域、更新时间，验证全部回滚；移除故障后原身份可正常重试。
3. 超长策略、6 类无效预算、熔断查询不可用均不留下写入或消耗身份。
4. 两个实际数据库连接/线程同时争用同一身份，只有一个创建成功，所有身份归属同一获胜任务。
5. 错误草稿作用域、已归档工作空间均拒绝且不消耗登录身份。

新增 `tools/test_agent_workbench.cjs`，执行真实 SFC setup 和模板，9 项测试：

- 保存草稿不调用启动，并展示两种按钮。
- 直接启动兼容原行为，仅调用一次创建/一次确认。
- 创建失败保留可重试输入和身份。
- 启动响应不确定时保留已创建任务入口，清除已消耗身份，不自动重试。
- 处理中重复点击只创建一次。
- 工作空间 A→B→A 后迟到响应不能启动。
- 卸载后的迟到响应不能启动或导航。
- 已保存后的迟到身份列表不能复活旧句柄。
- 切换代码模式时取消原 Web 启动意图，保留用户改过的任务名。
