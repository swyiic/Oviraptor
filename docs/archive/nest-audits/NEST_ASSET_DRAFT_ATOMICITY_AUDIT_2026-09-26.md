## 结论与范围

补证提交持久化恢复通过主库 809／导入器 30 和前端 70 项验证后，继续检查其他任务入口，发现资产列表入口 `create_sentinel_scan` 仍逐条自动提交任务、策略和目标，且目标使用 `INSERT OR IGNORE`。第二个目标失败可能保留半成品草稿；策略或目标被静默跳过也可能返回成功。

本次修复实际资产创建入口，不新增扫描能力、不启动任务、不连接外部目标、不修改历史任务。它不是 `confirm_sentinel_scan` 启动事务完成声明，也不是全部 Master Plan 完成声明。

## 实现

- Tauri 入口委托给可测试的 `create_sentinel_asset_scan_in`，从检查项目状态之前开始 IMMEDIATE 事务。
- 项目状态、资产归属、未移出状态和熔断过滤来自同一事务视图。熔断查询失败返回错误，不默认放行。
- 请求 asset ID 去重；重复 URL 按 asset ID 排序保留首个代表。去重在内存中显式执行，不用数据库忽略错误代替去重。
- 保留已有项目/资产筛选与扫描策略语义，未增加身份授权或继承其他任务凭据。
- 任务、策略、全部目标的每次 INSERT 必须实际写入一行。
- 提交前重新检查任务项目、名称、草稿状态、checkpoint、空执行路径、Web 类型、零 attempt，以及策略 JSON / environment；目标总数和每个目标的项目、资产、company、URL、queued 状态及零 attempt 必须一致。
- AFTER 触发器删除或改变内容即使 INSERT 报告一行，也不能返回创建成功；所有本次写入一并回滚。
- 成功只返回完整草稿；不创建 attempt、Agent run 或授权控制组，不占用草稿身份。
- checkpoint 分开说明排除资产和重复 URL，不再把不属于当前工作空间、已移出或无效选择一律说成“熔断区 URL”。

## 5 项新增后端回归

1. 同一输入包含重复 ID、同 URL 的不同资产、熔断资产、其他工作空间资产、已移出资产和不存在 ID：仅保存两个合法目标及精确策略，稳定选择 asset ID 较小的代表；无执行/身份副作用。
2. 草稿、策略和第二个目标分别注入 ABORT / IGNORE（6 组）：任务、策略、目标和身份快照不变；移除故障后可正常创建。
3. AFTER INSERT 删除策略、篡改策略、删除目标、改目标项目、改目标状态、改任务状态（6 组）：均拒绝并完整回滚。
4. 空选择、全被排除、归档工作空间和熔断查询故障：不影响已有任务和身份。
5. 另一个数据库连接创建草稿期间，已有写事务提交项目归档：创建返回项目已归档，不留下草稿。

## 后续真实缺口

本轮读到的通用 `confirm_sentinel_scan` 仍有以下未完成项，不能用“创建草稿事务已修复”替代：

- `draft` 状态检查与后续 `scanning` 写入不在同一事务；最终 UPDATE 没有同时比较预期状态/attempt。
- 启动期间熔断目标 UPDATE 的错误被忽略；应传播实际失败，并与目标快照一致。
- 冻结计划文件、工作目录、身份文件与数据库 attempt 交付需要故障后清理和崩溃恢复；只在数据库外层加锁不足以完成。
- scan 状态、目标 attempt、attempt ledger、当前结果表面清理和分支登记目前分步写入；后部失败可能保留“scanning 但未派发”的状态。
- 要把双窗口确认、暂停/取消竞争、失败后重试、故障清理及启动回执丢失纳入正式启动验收，不能仅加一条前端禁用按钮。

后续实现应冻结确切 attempt，原子认领和登记待派发执行，只有提交后才允许 worker 领取；失败清理只处理本次拥有的资源，不删除历史 attempt。文件/数据库间的崩溃窗口必须有可对账状态，不能靠模型猜测或恢复时自动重复启动。

更广泛的 Stage 9/10、非 HTTP 证据验证、工具隔离、知识生命周期和桌面/授权目标验收，继续按 Master Plan 推进；主机执行能力仍未启用。
