# 任务记录删除与后台结果同步：实现及验收

状态：暂停可靠性之后的有限增量，最终验证见第 6 节。不是完整人工结案、文件清理、恢复器或 Master Plan 完成声明。前置审计为 `NEST_PAUSE_QUIESCENCE_AUDIT.md`。

## 1. 删除的产品合同

“删除任务”是操作员明确确认后，删除数据库中的任务及其关联记录（包括受关联约束管理的对话和执行记录），不是软归档，也不是停止执行或清理磁盘。要保留可查询历史，应使用归档；本增量没有新增数据库恢复功能。

- 正在执行、正在暂停、未知状态、仍有真实执行所有权的任务不能删除。
- 存在未决请求、未结算费用/assignment、未交付指令或未确认进程/容器清理时，保留任务和证据并返回原因。仅改成 completed、租约到期或填写人工声明不能绕过检查。
- 删除入口不向持久化 PID 发信号，不读取任务路径作为删除授权，不删除历史 JSON、任务描述文件或 native 产物目录，也不跟随其符号链接。
- 独立重试子任务保留，仅解除指向被删除父任务的 `previous_scan_id`。
- 删除成功只表示数据库事务成功，不表示目标效果被撤销、工具已全数清理或磁盘空间已释放。
- 保留的文件可能包含敏感证据或认证相关产物；文件保留不是安全擦除。受控文件保留周期与回收机制仍需独立设计。

本次未删除生产用户任务或产物，只在隔离临时夹具中验证删除路径。

## 2. 修复的问题与后端实现

旧 `delete_sentinel_scan` 会按历史 PID 尝试停止进程，并依据持久化路径及默认目录删除文件；数据库删除、删除标记和外部副作用不处于同一事务中。现在该命令只调用 `scan_deletion.rs` 的 `delete_sentinel_scan_inner`。

处理顺序：验证任务 ID → 取得 scan lifecycle 所有权 → 开启 SQLite IMMEDIATE/FULL 事务 → 核对任务/删除标记 → 检查允许状态、真实执行所有权和未结义务 → 捕获子任务整行基线 → 写入删除标记、解除子任务父链接、删除明确关联记录 → 验证后置状态 → COMMIT。

真实所有权覆盖当前和历史 attempt 的 Web/source 分支、producer、target 与独立 native recon；已取得的锁一直保留到 COMMIT。进程/容器清理检查沿用暂停收口约束，不把没有登记当作所有浏览器后代已经退出的证明。

未结义务检查明确覆盖：pending native branch；未终止 run 或要求请求核对/证据完整性的停止码；未终止或预算未结的 assignment；lane lease；预留 token/request；未 received 的 specialist call；运行中/中断/无结束时间的工具调用；无回执或未关联成功工具调用的 HTTP claim；缺产物的 External Surface/Authorization 回执；未结束指令。收到响应头本身不能证明完整请求结果已收口。

删除标记和任务消失必须一起提交。无任务但存在标记时，重试幂等返回成功，不刷新标记时间；任务与标记同时存在则拒绝，不自行消除矛盾。COMMIT 返回不确定时明确报错，后续重试观察持久化结果，不重做文件或进程操作。

原有数据库外键负责 native 关联级联，旧表显式删除兼容。事务检查任务/父链接/明确关联记录已不存在、标记准确、所有子任务整行除父链接外不变。ABORT、IGNORE 或所检查范围内的 AFTER 触发器篡改均回滚；这不是对任意数据库触发器、任意未来新增表的全覆盖证明。

## 3. 后台同步不能绕过删除合同

后续取代说明：下面记录的是本删除增量当时的实现。后续已将历史阶段/recon 同步统一接入隔离导入器，完全移除它们对原生任务的投影及轮询修复，因此历史导入不再需要取得原生任务生命周期锁。删除入口自身的锁和未结义务检查保留。当前实现与回归见 `NEST_RESULT_SYNC_ISOLATION_AUDIT.md`；本文件第 6 节的验证数字仍保留为当时快照。

发现旧结果同步会根据删除标记直接清除仍存在的任务行，绕过上述一致性拒绝；另一条 recon 路径读取删除标记失败时会按“未删除”继续。

`result_ingestion_sync.rs` 新增共用准入检查，两个逐 scan 投影入口都持有同一 lifecycle 所有权直到该次投影结束。锁被占用则跳过；其他取锁/查询错误返回错误；有删除标记只跳过，不删除残存任务行。由此防止这两个入口与显式删除交叉执行、重新导入已删除任务或替删除入口擅自消除不一致状态。

范围限制：同步入口之前的 `repair_web_target_pollution` 仍不是逐任务 lifecycle 事务；历史 checkpoint/target/status 投影也没有因此全部原子化。本增量不能证明所有后台写入和原生状态投影都已协调完毕。

## 4. 实际 UI 行为

`SentinelBoard.vue` 的确认弹窗去掉“强制停止并删除”承诺，任务卡片统一显示“删除”，不再对运行中任务显示“强制删除”。运行中/暂停中解释后端拒绝原因；其他任务解释数据库关联记录删除、未决状态拒绝、文件保留，并提示归档用途。

调用进行中不能重复提交、关闭或改选删除对象。失败保留选择、预览、发现和弹窗，展示后端原因，不伪造成功或清空详情。成功文案为“任务及关联记录已删除；历史源文件与任务产物文件已保留”。
