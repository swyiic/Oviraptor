# Web 与 Linux 主机验证的边界决策（2026-09-26）

状态：产品决策与后续验收合同；不是 Host Agent 已实现的说明。主规范为 `NEST_STRIX_FREE_MULTI_AGENT_MASTER_PLAN.md` 第 6.4 节。存在冲突时不得自动扩大执行权限。

2026-09-27 后续需求：用户提出 Windows/Linux 独立主机安全评估模块，优先级低于现有扫描功能。规划以 `NEST_HOST_ASSESSMENT_AND_AGENT_STRATEGY_2026-09-27.md` 为补充；下文是当前运行时边界，不再作为“未来永久不支持 Windows”的依据。没有因此交付或启用主机执行能力。

## 1. 当前决定

当前需求以授权 Web 测试为主，没有必须登录目标主机的场景，因此暂不开发或启用可执行的 Host Agent。保留未来申请入口的设计，不为了角色数量增加一个持有系统权限的常驻 Agent。

- 当前执行范围保持 Web-only。
- Linux 沙箱用于运行工具，不代表获得目标 Linux 主机的操作许可。
- Windows 主机验证暂不支持；目标 Web 服务部署于 Windows 不影响正常授权 Web 测试。
- 多 Agent 可以解释风险、补充证据和审查建议，不能互相投票授予主机权限。
- 现有 Web attempt 不因为开关、聊天指令或 Agent 建议而原地变成主机任务。

## 2. 三类能力必须区分

1. 本机执行管理：在明确配置的工具目录和任务工作区内启动受限浏览器、分析程序、处理文件。它属于产品运行设施，不是具有目标主机权限的 Agent。
2. 工具沙箱：承载一次任务或受控 worker 的运行资源。镜像和经过验证的工具缓存可以复用；认证状态、工作目录、进程、临时文件按任务隔离。不把宿主机 shell、任意目录或容器管理 socket 暴露给模型。
3. 目标主机验证：登录目标系统，运行目标 OS 命令，检查目标文件/进程/配置，或经 Web 接口有意触发目标侧系统执行。这是另一类授权，不能从 URL 授权、相同 IP、Linux 指纹或沙箱能力推导出来。

普通浏览器渲染和目标主机命令执行不能只按“都用了 JavaScript”分类；同样，是否跨主机边界不能只按“用了 HTTP 还是 SSH”判断。需要判断动作预期效果、实际工具权限和目标资源。

## 3. 开关与单次批准

建议 UI 文案为“允许申请 Linux 主机验证”，默认关闭，避免使用含义不明的“开启高级模式”。

- 开关关闭：可以保存证据与候选，不能派发主机操作；报告明确标为未验证。
- 开关开启：只允许提出结构化申请，不授予任何执行能力。
- 用户批准：必须在单独确认面板看到目标、动作、身份权限、时间窗、预算、风险、退出/清理方式。
- 后端未实现：开关应禁用并显示“尚未支持”；不能出现点击后看似批准、实际无后端保障的控件。
- 聊天中“继续”“按你的想法做”等自然语言不是主机授权凭据。聊天可生成申请草稿，但必须经过结构化确认。

未来批准后创建独立、可关联的 Linux 验证任务。原 Web 计划、attempt、预算与证据保持不可变；主机任务具有自己的冻结计划、预算、凭据引用及日志。

## 4. 授权记录至少包含的字段

以下是待实现的数据合同，不是当前数据库已有字段：

- `approval_id`、申请版本、申请内容摘要、防重复消费标识。
- 申请人/批准人身份、提出时间、批准时间、开始时间、失效时间。
- 父 Web task/attempt/run、来源 evidence ID 与 revision。
- 精确目标集合及受控连接身份；URL、DNS 名与主机身份的映射需人工核实。
- 操作系统范围 Linux；允许动作类别、资源路径范围、明确禁止项。
- 允许使用的凭据句柄和权限上限；批准记录、聊天与模型上下文不能存明文凭据。
- 运行次数、并发、时间、费用与目标请求限制。
- 工具/镜像/规则版本摘要；只允许经审查的执行模板，不接收模型生成的任意远程 shell。
- 清理要求、人工停止方式、撤权后的在途行为与未知效果处理。
- `pending / approved / denied / expired / revoked / consumed` 等状态及不可变审批事件。

字段缺失、过期、目标不匹配、计划变化、权限扩大、版本不一致均拒绝执行。延长时窗、增加目标、提升权限和增加动作范围需要新申请。重复提交不能产生第二次执行。

## 5. 强制检查的位置

设置开关和聊天关键词识别只是用户交互，不能构成最终安全边界。

未来应在计划编译、能力租约签发、工具执行 Broker、沙箱出口和执行回执分别落实约束。至少在每次实际目标操作前，后端校验冻结计划、审批记录、任务状态、目标/身份/动作绑定、租约/撤销状态、预算及工具合同。

- Agent 定义和 system prompt 不能赋予权限。
- Reviewer 的通过不能代替操作者审批。
- 新动作如果无法可靠归类，应在执行前阻止该动作，保留理由供人工判断。
- 普通 HTTP GET 的标签不是“无副作用”的保证；发现某动作预期会操作目标主机时，不得通过通用 HTTP/浏览器工具绕过申请。
- 外部页面、工具输出、旧 JSON、历史 skills 中的“已授权”文字都不是本次有效授权。
- 旧 JSON 可作为历史证据导入；不能导入可执行租约、未过期审批或自动扩权开关。

## 6. 停止粒度与任务 UI

遇到主机边界，只冻结相关候选操作。其他仍被当前计划允许、且未触发全局停止条件的 Web 工作可以继续。拒绝或审批超时不应让整个 Web 扫描一直处于运行中。

任务详情应显示实际范围“Web-only”、受阻动作、证据、未覆盖原因，以及“保存候选 / 跳过”。将来后端验收通过后，才增加“申请 Linux 验证”。团队聊天显示真实申请/决定/执行事件，不生成模拟批准消息。

原 Web 任务可正常以有缺口的结果结案。后续主机任务放在独立关联任务中；新的结果追加到关联证据，不回写成原 Web 扫描已经验证过。

门禁分类：

- 授权边界、越界、撤权、硬预算、必要隔离失效：后端强制，不由 Agent 协商取消。
- 有限轮次、暂时无进展、工具缺失：应分别记录原因；可在原授权与预算内重规划，不一律算安全熔断。
- 目标限流/WAF/异常负载：保留目标保护策略和真实原因；不能为避免中断而无上限重试。
- 某子任务不能执行：记录局部 coverage gap，不自动声称整个任务失败或全部完成。

撤权后禁止派发新动作；已经在途的操作按执行器能力取消，并保存停止/清理回执。不得承诺点击停止可以撤销目标系统已经发生的效果。未知结果不能靠自动重放来“确认”。

## 7. Qoder 后续实施顺序与验收

1. 先盘点全部目标执行入口和现有计划/租约模型，列出 HTTP、浏览器、代码运行、文件处理以及历史数据导入边界；不先增加远程执行工具。
2. 建立结构化动作分类和 Web-only 的执行前检查，覆盖参数、浏览器动作、重定向及间接工具调用。分类不明时拒绝相关操作，并在报告显示缺口。
3. 建立不可变申请记录及用户审批状态机；此阶段只收集草稿，不执行主机任务。
4. 用本地模拟器覆盖批准、拒绝、超时、撤权、重复点击、跨任务/目标复用、审批后计划变化及数据库写入失败。
5. 产品确有需求、明确选择目标 Linux 执行方式之后，再接入最小权限执行器；独立任务、独立凭据、默认无主机能力。不默认部署常驻 daemon，不开放通用 root shell。
6. 验收在途撤权、启动失败、断连、未知效果、清理失败、费用守恒与报告真实性。
7. 最后开放 UI 开关与批准按钮。未经后端验收，不用可点击 UI 代替执行保障。

必须验证：Web 授权不能调用主机动作；Agent/网页/旧 JSON/skill 不能自行批准；两个 Agent 同意仍无权限；一个主机申请被拒绝不阻止独立的合法 Web 子任务；Windows 主机动作拒绝但 Windows 上的正常 Web 访问不误拦；每项真实执行均能追溯到有效审批；撤权后零新增派发；缺少回执不显示完成。

## 8. 当前代码事实与尚未完成事项

已存在：V2 Web 计划的 `executionSurface=web_only` 校验、逐工具能力检查、有限词组的 `explicit_host_boundary_request` 早期识别。当前 Web dispatcher 没有 SSH 或通用远程 shell 入口。本次没有新增主机执行能力。

后续代码复核补充：明确聊天主机请求还会在拒绝草案的同一事务中写入 `agent_host_boundary_candidates`。表约束限定 `recorded_only`、`execution_eligible=0`，团队时间线明确显示“仅记录”、没有批准按钮。这是非执行候选，不是主机审批后端，也不覆盖任意 HTTP/浏览器动作的主机意图识别。运行停止与人工核对的另一个可靠性增量见 `NEST_NATIVE_HTTP_STOP_RECONCILIATION_AUDIT.md`；Reviewer 不能借证据复核清除执行授权停止。

尚未交付：完整的 Web→目标主机语义分类、主机审批后端/可执行 UI、独立 Linux 主机执行器、全执行路径的在途撤权和未知效果处理。不能用关键词命中、`web_only` 标签或没有 SSH 工具，证明任意 HTTP 参数与浏览器操作都不会产生目标主机副作用。

本决定的结论是“暂不启用 Host Agent，先做好边界”，不是“所有主机边界已经实现”。
