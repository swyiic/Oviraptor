# 通用 HTTP 执行器逐请求持久化审计（2026-09-27，Asia/Shanghai）

状态：实现与全量回归已落地；不是整个 Master Plan 的完成证明。本轮只访问 localhost 模拟服务，未部署、未测试外部授权 URL，未新增主机操作能力。

## 1. 修复的真实窗口

旧路径在 `agent_http_exchange` 内先增加内存计数，再发送；工具结束与 checkpoint 持久化发生在后面。发送后、工具结束前退出，可能使界面和共享预算漏掉一次已经开始的请求。

现路径为：权限和 scope 检查 → IMMEDIATE 事务内再次检查权限、当前 attempt、运行中的 invocation、共享预算和持久化占用 → 提交成功 → 增加内存计数 → HTTP 发送 → 持久化响应头回执 → 继续响应体处理和独立证据持久化。

一次模型工具内的多个 HTTP exchange 分别领取，不只给最外层工具记一次。数据库事务不跨网络等待。

## 2. 版本边界与计数语义

- 新表 `agent_http_budget_origins` 为明确预算继承链的最早 attempt 保存不可变历史基线，schema version 为 1。
- 新表 `agent_http_request_claims` 保存之后的逐请求占用，绑定 scan、target、预算来源 attempt、实际 attempt、run、invocation、调用内请求序号、tool、identity 和请求摘要。
- 安装基线前继续兼容读取历史 Native JSON；安装后以“历史基线 + 新占用记录”作为 Executor 权威计数，checkpoint 只作为投影，不能再与 journal 相加。
- checkpoint 高于 journal、请求序号出现缺口、绑定损坏、来源版本不支持等情况返回不可核验，不默认为零。
- resume 只沿已有类型化继承关系读取同一预算；fresh 不自动继承旧占用。不得修改历史混合账本以伪造精确流量。
- `executorRecordedRequests` 仍是执行器已记录的请求尝试／预算占用，不是成功响应数，也不是已经到达目标的证明。
- 新增 `executorUnresolvedClaims`，是上述 Executor 总数的子集，不在共享预算中再次相加。旧快照没有该字段仍可读，UI 不为旧数据补造新的未决数。
- External Surface 与 Authorization 的既有独立占用语义不变；所有新 claim 在同一写事务中检查跨角色共享上限。

## 3. 回执的严格含义

`response_status=0` 表示没有持久化“已收到响应头”的回执。它可能是尚未发送、连接失败、请求在途、响应丢失或回执写入失败；一律保留占用。

非零状态只表示 HTTP 响应头已收到并持久化。响应体可能继续失败、被截断、触发保护策略或无法保存证据。该回执不能代替 HTTP 私有文件、evidence graph 完整性或 Reviewer 的事实资格检查。

请求摘要不存明文 URL 查询、请求体、Cookie 或 Authorization。摘要只用于匹配请求，不是秘密的加密存储或不可猜测性的保证。URL fragment 和空请求体按实际 HTTP 语义归一化，不能用它们绕过同一未知请求的拒绝重放。

## 4. 失败、撤权与恢复

- claim 写入、写入后复核或提交失败：不发送目标请求；静默 `RAISE(IGNORE)` 不能伪装成功。
- claim 提交后退出：占用仍在。落后的内存／checkpoint 不能继续领取并覆盖已有占用。
- 同一预算继承链存在相同逻辑请求的未决 claim：拒绝重复派发。调用内序号唯一约束阻止同一 invocation 重启后再领取已用序号。
- 已收到响应头但回执持久化失败：该请求继续保留为未决，不自动重发以“确认”。
- 暂停／撤权后可以登记先前在途请求的迟到响应头，但该本地登记不能重新激活任务、授予能力或发布新的执行动作。
- 基线不可更新；已收到响应头的记录不可再次改写。删除任务时由外键清理关联记录，不妨碍用户删除任务。
- 现有未完成目标工具的恢复拒绝机制继续有效。这里没有提供新的“忽略未知结果继续执行”按钮。

## 5. 已有验证

新增 9 项 Rust 定向测试：

1. 一个真实 invocation 的两次 localhost 请求逐条登记；旧 checkpoint 落后仍保留总数，checkpoint 追上后不重复计费，反复读取不发请求。
2. claim 后没有发送仍保留占用，旧计数和相同未知请求均拒绝重放。
3. claim 的忽略、异常、写后删除故障全部回滚，真实目标观察到零请求。
4. 目标已返回、回执写入忽略／异常：保留未决，占用不返还且不再请求。
5. 两个并发领取者只有一个成功。
6. 非运行 invocation、预算耗尽、能力撤销在领取前拒绝。
7. 暂停后的迟到响应头可以结算，任务不复活，回执和基线保持不可变。
8. resume/fresh、不同目标隔离、checkpoint 超出 journal 与损坏 attempt 绑定。
9. fragment／空 body 归一化、错误身份、错误 attempt 回执拒绝，以及任务删除级联清理。
