# 补充任务提交跨页面／重开恢复验收

## 本次修复

先前工作台只在组件内保存补充任务的请求键和冻结输入。数据库虽能按原键幂等返回原任务，但组件卸载或应用重开后丢失原键，无法可靠区分“任务已创建但响应丢失”和“尚未创建”。

本次将提交意图先保存到本地 SQLite，再进入任务创建事务。重新打开同一补证来源时只读恢复原提交；用户再次保存才会沿用原请求，或者打开其已创建的任务。不会在启动、挂载、刷新或恢复时自动建任务、捕获身份、调用模型或开始扫描。

本增量替代 `NEST_GAP_FOLLOWUP_HANDOFF_AUDIT_2026-09-26.md`、`NEST_GAP_REVIEW_CLOSURE_AUDIT_2026-09-26.md` 中“请求键只在组件内／该补证入口跨卸载重开对账尚未实现”的旧状态。它不代表通用任务启动、模型派发或全部崩溃恢复已完成。

## 后端合同

- `agent_gap_followup_submissions` 保存 request ID、source scan、assessment message、冻结输入、hash、永久 created scan ID 和 pending/released 状态。输入包括身份句柄，不提取或复制其凭据；不使用浏览器 localStorage。
- 输入上限 256 KiB；UUID、有限预算及规范序列化必须有效。保存后字段不可修改，released 不可恢复为 pending。
- `(source_scan_id, assessment_message_id)` 仅允许一条 pending 记录。双窗口使用不同请求键，也不能同时为同一未结束提交创建两个任务。
- 创建前用独立 IMMEDIATE 事务保存并验证 journal 的实际内容和 pending 状态；INSERT 被 IGNORE、删除或改状态时不能继续创建。
- 真实创建仍使用原来的原子任务/身份/来源写入和请求 hash 幂等机制。创建事务内部再次检查 released，拒绝在用户结束提交后迟到的旧请求。
- 只读恢复验证冻结输入、hash、来源键与实际创建收据。已有任务返回实际状态，即使任务不再是 draft，也不会重启或重建。
- 创建失败后，只有另一个加锁事务确认不存在该请求的任务，才可以释放记录并返回明确拒绝。对账失败或出现已提交任务时保留未知状态，不把不确定结果当作可以换键重试。
- 原任务删除不受提交表外键阻止。已创建补充任务被删除后，其 provenance 收据会随任务删除，但 journal 永久保留 created scan ID；旧请求不得因此重新创建任务。界面显示“已创建任务已删除”，显式结束仍需匹配原 ID。
- created scan ID 与任务、身份及 provenance 在同一创建事务中保存；写入被 IGNORE 或保存值不符时整体回滚。该 ID 非空后不能修改，释放提交也不能抹除。

## 显式结束提交

UI 提供“结束原提交并重新准备”的确认面板：

1. 未创建任务时结束提交，后端写 released；迟到创建请求被拒绝。
2. 已创建任务时必须携带用户已看到的确切 task ID；任务被保留，不删除、不停止、不启动。
3. 如果页面原以为尚未创建，但后台刚刚提交成功，结束操作拒绝，页面重新显示实际任务；不得自动再次结束。
4. 结束操作响应丢失时丢弃匹配的内存副本，后续重新读取权威记录；页面 A→B→A 不复用被结束的旧请求。
5. 结束成功后重新选择身份、显式保存，才能产生另一份补充草稿；不存在后台自动重放队列。

## UI 与生命周期

- 挂载及来源变化时恢复记录；保存前再次只读对账，防止另一个窗口在此期间已提交。
- 对账失败阻止新建，提供“重新核对”；不允许查询失败默认当成“没有提交”。
- 冻结提交的任务名、模式、预算及身份句柄数量明确显示；编辑普通表单不会偷偷改变原请求。
- 已保存结果仅在用户点击时打开；draft 去控制组准备页面，其他状态打开实际任务，不再次确认执行。
- 迟到查询、迟到创建、A→B→A、卸载和迟到结束结果均有代次／来源绑定检查。
- 结束成功清除已选择身份并停止该表单的身份捕获轮询；不将旧身份自动带入另一份任务。

## 回归覆盖

新增 9 项 Rust 测试：

1. 保存 pending 后关闭连接并重开，恢复完全相同输入；创建成功后再重开，读取和重放只返回原 draft，无新增执行副作用。
2. released 拒绝迟到创建；已提交任务必须以确切已观察 ID 结束；重复结束幂等，任务保留，原成功请求永久返回原任务。
3. 创建事务注入失败，没有半成品任务，只有证明未创建后才释放；新显式请求可继续。
4. Journal ABORT／IGNORE／AFTER 删除／AFTER 改状态阻止创建；释放写入 IGNORE 保留可恢复状态。
5. 输入冲突、来源错配、不可变字段修改和模拟磁盘 hash 损坏被拒绝。
6. 双窗口不同 request ID 竞争同一来源，只创建一份任务。
7. 结束与创建竞争只有一个权威结果；不能在未观察到成功创建时同时报告取消成功。
8. 已创建任务删除后保留永久收据，恢复与旧请求均不能重建；来源任务也可以按原路径删除。
9. 记录 created scan ID 被静默 IGNORE 时，任务和 provenance 一并回滚。

新增 10 项真实 Vue SFC 测试：跨组件重开恢复原 payload；已提交任务重开只导航；对账故障阻止创建并可重试；来源 A→B→A 的迟到读取；卸载期间预检不能迟到创建；结束发现并发提交后需第二次显式决定；冻结内容安全转义；结束迟到成功／响应丢失不保留已取消请求；已删除任务恢复不得重建且结束必须携带原 ID。

旧的迟到创建测试补充等待只读预检完成，确保测试真正进入创建 IPC 后再切换页面；没有移除原生命周期断言。首轮旧测试因未进入创建就拒绝未消费的 promise，产生 unhandledRejection，日志保留为 `ui-initial.log`，不能当成最终通过记录。
