# Oviraptor / Strix SRC 能力与环境要求

本文档描述 Web 调查策略 schema v4 的真实能力边界。任务结果中的“扫描完成”只表示本轮有界计划结束，不表示所有攻击面均已测试。

内置范围以公司 SRC 规则作为最低基线，并额外按 OWASP ASVS 5、Web Security Testing Guide 与 API Security Top 10 2023 维护扩展风险族。标准用于防止遗漏，不表示每个类别已经在当前目标上执行。

## 已内置，无需额外环境

- CDP 页面渲染、运行时请求、请求头名称、参数和响应结构采集；
- JS/AST 接口候选、运行时接口与静态资源/遥测分层；
- 基础配置、信息泄露、已有真实参数的注入候选与只读验证；
- 单身份未认证边界、登录状态和普通 401/403 边界记录；
- 证据门禁、API 去重、覆盖账本、Token/费用与断点续跑；
- Quick / Standard / Deep 分别最多 4 / 12 / 24 条验证契约。

## 无需开关，但需要真实任务输入

### 身份与权限差异

在任务中绑定至少两个由独立 WebView 捕获的有效身份。两个身份必须使用不同认证材料并共享目标作用域。只有同 method、URL、请求形状和业务对象上下文的双侧完整响应才能形成越权证据。这不是专项能力开关，而是系统无法凭空生成的业务证据；单账号任务仍会自动执行其它适用类别。

### 附加专项 Skill

内置“业务前端深度分析”始终自动启用，Asset 入口和 Strix 入口使用同一后台解析器，不需要用户选择。Strix Web 高级设置中的自定义 Skill 与补充要求只用于可选的业务增强；不填写不会关闭 SRC 默认流程或专项适配器。

## 自动内置的专项适配器

### HTTP OAST 回连

- 每个目标启动时由 Oviraptor 自动创建唯一回连 token、HTTP 监听和命中查询地址；
- Strix 从挂载的 `src-capabilities.json` 取得 callback/poll URL，不需要人工填写；
- 用途：盲 SSRF、XXE、异步命令执行等无回显验证；
- 如果目标网络不能回连运行 Oviraptor 的工作站，只将该目标的 OAST 类别标记为网络不可达，不影响其它验证。

### 原始 HTTP 协议

- Oviraptor 自动挂载零第三方依赖的 Python 标准库适配器；
- 单次原始请求最大 64 KB、响应最大 256 KB、超时最大 15 秒，Host 必须匹配准确目标；
- 用途：CL.TE、TE.CL、TE.TE、HTTP/2 降级等协议差异；
- CDP、fetch、curl 或普通高层 HTTP 库不能代替该能力。

### 条件竞争

- 内置最大并发 64、单契约最大尝试 128 次的并发调度器；
- 写请求只有在契约提供业务不变量与 `cleanup.url` 时才可执行；
- 用途：额度、库存、优惠券、订单状态等并发一致性；
- 不具备可恢复状态时自动保留候选，不执行写入。

### 受控写入

- 无全局开关，按每一条验证契约自动判断；
- 契约必须包含测试账号/隔离数据、清理或回滚接口、次数上限和业务不变量；
- 用途：上传、创建临时对象和能够完整清理的状态变更；
- 永远不自动授权不可逆删除、真实资金结算、外部消息以及持久账户/权限变更。

## 唯一可能需要的一次性网络条件

OAST 接收器运行在当前 Oviraptor 工作站。内网目标通常可以直接访问自动选择的工作站地址；如果被测系统位于不能回连办公网的隔离区、云 VPC 或互联网，则需要在网络层把一个可达的 HTTP 地址转发到 Oviraptor 的监听端口，或者在该网络中运行 Oviraptor/Worker。这里不需要额外安装 Python 包或扫描器，但网络路由、防火墙和入口策略必须允许目标回连。

权威 DNS OAST、移动端/native 请求、服务间接口、未被 Web 前端触发的内部 API，以及复杂长事务的测试数据仍取决于组织网络和业务测试数据。系统会把这些情况标成未触达或缺少业务前置条件，不会要求用户记忆开关，也不会伪装成已测试。

## 验收口径

- “已确认”：必须有可重放请求、对照响应、身份/对象上下文和安全影响；
- “未发现”：仅表示已列出的契约按计划执行且没有安全效果；
- “未测试”：缺少身份、工具、回连、状态、样本或授权；
- “扫描完成”：本轮队列、预算或正常停止规则已经收口；
- 不承诺零漏报或全输入覆盖，但不允许把未测试攻击面描述为安全。

## 人工补位

每个 URL 的确定性调查会根据真实接口、页面动作、参数、身份数量和缺失前置条件生成目标特定的 `manualDeepDive`。Quick / Standard / Deep 最多保留 3 / 5 / 8 条，并按同级账号与对象权限、敏感业务状态机、身份生命周期、文件、服务端集成、实时协议、并发、资源限额、客户端信任和影子 API 排序。

这些条目统一标记为 `coverage_gap_not_vulnerability`，不会进入漏洞数量或 AI 可验证队列。每条必须包含已有证据、缺失证据、人工步骤和停止条件；AI 最终摘要最多保留前三条，不再额外消耗模型轮次重新生成泛化建议。
