# Hunter UI、配置与资产来源修复（Fix10，2026-10-20）

## 用户当前要求

- VPN 保持现有配置；用户关闭 VPN 后测试 Hunter。
- 主操作必须清楚区分保存 Key 和账户验证，不允许验证旧 Key 或误以为保存失败。
- 修复设置布局；资产列表以“资产来源”替代“所属项目”，合并展示 FOFA / Hunter 来源。

## 修复

1. Hunter 主按钮：输入新 Key 或修改选项时显示“保存并验证 API Key”。先等待保存成功，再发出账户验证；保存失败保留输入且不调用验证；验证失败明确显示“API Key 已保存；账户验证失败”。处理期间防止重复点击。副按钮为“仅保存，不验证连接”；没有改动时禁用。
2. 已保存 Key 不回显，不把空输入当成删除。移除 Key 放在独立展开区域并需勾选。界面显示待保存 / 已保存状态，保存和验证反馈分开。
3. Hunter 可选择独立直连或跟随业务网络。默认直连仅在请求客户端使用 `no_proxy()`，账户验证和自动翻页共享该策略；系统 DNS、系统路由、网卡、FlClash、全局 VPN 与其他模型/FOFA 配置不变。旧设置只读兼容，显式保存时才写入独立网络偏好，仍使用原修订号约束。
4. 独立直连不能绕开 TUN / 全局 VPN。用户关闭 VPN 后再验证。本轮无 VPN 切换、附加规则、网卡绑定、公共 DNS 覆盖或真实带 Key 的 Hunter 请求。
5. 设置页改为固定视口下主栏与内容独立滚动；大任务提醒不再出现在配置页。Hunter 表单明确间距、按钮分组、窄窗换行、错误信息和账户余额卡片，不再使用原始 JSON 作为主要账户显示。
6. 资产默认列和字段选择删除“所属项目”，改为“资产来源”。已有显示字段会将旧 projectName 位置迁移为 assetSources，保留其他自选字段。读取当前 provider 和合并来源回执中的 provider / source / observation，显示 FOFA、Hunter 或 FOFA + Hunter；缺失来源显示“历史来源未记录”，不猜测旧数据来源。
7. 双来源资产分两行显示来源与状态。“双来源发现 · 待复核”不代表平台已证明业务归属；只有现有人工 decision=confirmed 时显示“已确认有效”。导出同样包含来源并区分有效性。旧 projectName 导出协议保留兼容，但新界面不再显示该列。

8. 自主探测面板将目标、三项运行限制、Hunter 授权与操作区分开。修复原网格 `input{width:100%}` 误作用于复选框导致的错位；复选框使用独立尺寸与说明，积分说明和数据使用说明分层显示。未设范围显示明确提示；缺少 Hunter Key 时复选框视觉状态为未配置而不是误显示已授权。

## 验证与边界

- 账户保存/验证顺序、403 后保存状态、保存失败保留输入、重复点击、资产来源及原有 UI 回归通过；发布前执行 TypeScript 与 Vite 构建。
- Hunter 分页/发现/网络设置使用临时数据库回归，导出使用真实生产服务配合临时数据库；不会写入真实业务数据库。
- 通过本地浏览器渲染生产 Vue 组件与实际 CSS，使用合成数据观察保存成功但 403、单来源、双来源待复核、双来源已确认有效。预览不连接 Tauri、真实 Hunter 或业务数据库。
- 当前 VPN 开启时，无 Key 的普通/跳过代理请求均返回 HTML 403。依据用户最新要求，没有继续绕过 VPN；关闭 VPN 后的真实账户验证由用户执行，不能宣称 403 已在线验收。
- 发布 App 保留 Fix9 的独立 Host 资源；本轮更新 Rust 二进制和桌面 UI，不将保留资源宣称为最新 Host。未自动替换系统安装目录，未启动新包访问真实数据。
