# Agent 监督式扫描架构 + 展示信息去留分析

> 目标:strix 退场后,让自有 agent **参与扫描全生命周期**、在固定硬顶内自适应;
> 去掉 strix 时代的"微限制"与冗余观察脚手架;把展示精简为"用户价值 + 监督面"。

## 1. 背景

- **strix 时代**:agent 较不可信 → 用大量**微限制**(root 3 轮 / 4 本地调用、模式级起始软预算、无进展熔断)约束它,
  用大量**观察脚手架**(结算态、回执校验、尝试账本、停因诊断、刚性过程分栏)盯着它。
- **现在**:自有 agent + fork 刚建的 **§9 监督地基**(`agent_stage_decisions` 表 + 裁决器 + 时间线)。
  那些微限制和观察脚手架很多已是 strix 遗留,该由"有界监督"取代。

## 2. 不可破的硬约束(使"放宽"安全的前提)

1. **固定硬顶**:每目标 `900k token / 22 请求`(`hard_token_budget` / `hard_request_budget`)。
   **agent 够不着、不可自抬**。这是真正的安全地板;下面所有"交给 agent"都在它之内。
2. **注入纪律**:agent 分析的是**不可信目标内容**(瑞数混淆 JS、HTTP 响应)。
   目标内容**绝不能**设置/抬高任何预算或限制。监督信号**只读**喂给 agent;
   agent 的控制输出一律被内核 **clamp 到硬顶**,目标内容不进入控制路径。
3. 凡"交给 agent"的只能是**软参数**(轮次节奏 / 深度 / 继续或收口 / 哪条子线)。
   硬顶、WAF/验证码门禁、并发上限、注入边界 **不交出**。

> 结论:root 轮次/软预算这类是软旋钮,可交 agent;硬顶/WAF/并发是地板,保留。
> "删微限制"安全 **当且仅当** 硬顶仍在兜底 —— 这正是本次已做的前提。

## 3. 监督式生命周期架构

**现有地基(已在,不是从零):**
- root 本就是 **ReAct 循环**:看证据 → 决定派谁 → 收结果;工具含 `capability_budget.read`(**已能读自己的预算/限制**)。
- 子任务跑完**回报结果**,结构化证据包同步给 agent。
- **§9**:`agent_stage_decisions`(表)+ `stage_adjudicator`(裁决器)+ `AgentStageTimeline`(时间线),
  记录"agent 在哪阶段、什么结果、决定了什么、第几档" —— 这就是监督决策的落点。

**要新增的反馈闭环(每个决策点):**
- **扫描 → agent(只读信号)**:当前用量 vs 硬顶、各子任务产出摘要、进展信号(新端点/响应差异/证据)、覆盖缺口。
- **agent → 扫描(有界控制决策)**:继续/收口、下一步派谁、深度、是否再加轮次、把预算导向正在产出的子线。
- **内核执行 + 记账**:所有授予 **clamp 到硬顶**;决策写入 §9;目标内容不进控制路径。

**全生命周期 + agent 监督点**(由固定管道 → agent 看产出决定下一步):
`bootstrap → spa_api_mapper → external_surface → web_executor →(按需 follow-up / greybox 复现)→ 收口`

## 4. strix 时代限制的去留

| 限制 | 原作用 | 处置 | 理由 |
|---|---|---|---|
| root 轮次 3 / 本地调用 4 | 约束 strix 空转 | **已抬成灾难级兜底(48)** | 真正兜底是 22/900k 硬顶;3/4 是 strix 遗留的中间约束,刚好卡死 3 子任务管道 |
| 起始软预算(模式级 请求/Token/超时) | strix 预算起点 | 转为 **agent 顾问值**(自适应,硬顶内) | 本就是"软起点、有进展就继续";交给 agent 监督分配 |
| 无进展熔断 `agentNoToolTurnLimit`(默认 6) | 防空转 | **保留为默认兜底** | 打瑞数这类长时间零进展目标时,防止一路烧到硬顶白花钱 |
| 切片预算 `maxSliceReads`/`maxCumulativeSliceChars` | strix 静态读限(且上游未赋值=0=关闭) | **已开启 + 深扫加宽**(普通 3/42K,深扫 5/96K) | 复杂业务前端需要多读几段业务切片 |
| 硬顶 22/900k、WAF/验证码、并发上限 | 安全地板 | **保留,不动** | 防失控烧钱 / 防打爆真实目标被封 / 防注入资源耗尽 |

## 5. 展示信息去留(执行概览 + 结果证据)

**框架**:每块归为 —— (a) **strix 观察脚手架**(盯 agent 用,用户少看);(b) **用户真实价值**;(c) **监督面**(新架构要显式展示的)。

### 执行概览(NativeRunStatus + AgentDialog)
- **保留并提升为监督面(c)**:§9 Agent 介入时间线(哪阶段/决定/第几档)、分支执行状态(源码/Web)、
  **成本用量 vs 硬顶**、进展信号。→ 这正是你要的"把一部分信息展示出来" + 监督窗口。
- **精简/默认折叠(a)**:结算态细节(行政结案/封存/回执待核)、停因诊断、尝试账本 —— strix 审计残留,
  收进"诊断/高级",出问题再看。
- **过程五分栏**(investigation/opportunities/trace/attempts/routing)→ 合并为"时间线 + 按需展开",别硬分五栏。

### 结果证据(SentinelSourceResults + result tabs)
- **保留(b)**:summary / vulnerabilities / api / endpoints / fingerprint —— 真结论,用户价值。
- **精简(a)**:source-token 块、attempt-ledger 块 → 并入成本/诊断,默认折叠。
- "结论在别处、分析交给主 Agent 对话"的**刚性分隔**是 strix 约束,可放宽让结论就地可读。

> UI 实现与 fork/Opus 那条线**协调**(这些 .vue 组件归他们在改),本文档只定去留原则,不在此改组件。
