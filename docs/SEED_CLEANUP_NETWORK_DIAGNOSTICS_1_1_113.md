# 种子核验网络诊断（1.1.113）

真实回执中大量官网/公开 DNS 请求只保存 `error sending request`。reqwest 的 Display 隐藏了底层连接、代理和 TLS 因果链，无法区分超时、连接拒绝和证书校验错误。

本次修复：

- 公开 DNS、CT、官网请求和正文读取保留有界错误因果链；请求错误带 timeout/connect/configuration/request 分类。
- 最多六层，每层最多384字符。完整 URL、代理凭据、查询参数、认证/密码/Token/Cookie 字段脱敏后才进入原有持久回执与界面。
- 不修改 VPN、配置、TLS 校验或路由，不把网络失败当作资产不存在或主体无关。证书独立证据在正文读取失败时仍保留。
- 旧历史回执不改写、不猜测底层原因，不重置来源次数；后续原任务的请求和有限重试自然保存新诊断。

验证：旧实现中“连接拒绝”和“超时”两个真实本地网络回归失败；修复后资产发现完整回归404项通过、0失败、7项显式快照或外网检查未运行；安装保护79项通过。另检查嵌套 TLS 原因能保留，嵌套 SOCKS 凭据、查询 Key 与认证信息均不泄露。TLS 原因链测试为构造错误，不宣称真实目标的每一次失败均已还原。生产样例以安装后原任务回执为准。

完整核验仍由同一个任务执行；诊断修复不是本轮全量完成证明。配置、原始资产、人工决定、付费模型回执和原补证次数保留。
