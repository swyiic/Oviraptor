# Nest 与主 Agent 的统一执行规划

日期：2026-10-26。源码：`/Users/swyiic/Desktop/Rust/Oviraptor`。

## 结论

保留一个主 Agent 对话入口。Nest 是 Agent 可调用的扫描执行与证据工作台，负责计划准入、目标执行、进度、费用、暂停恢复、证据和独立复核。Nest 不再承担第二套日常聊天。

这不是重写 Nest 内核：复用已经持久化的任务、尝试、派发、回执和预算。先统一产品入口，再补通道缺口，最后验证执行闭环。不能通过删除确认按钮、把所有错误改成成功或重建任务来实现“顺畅”。

## 用户只需要的流程

### 谁负责哪一层

主 Agent 管用户意图与跨模块目标；Nest Root 管一项已冻结任务的执行调度；Worker 管一次具体动作；独立 Reviewer 管证据裁决。它们是上下游执行层级，不是四个会话，也不能互相宣布完成。

主 Agent 的“本轮已答复”只代表一轮聊天结束，Nest 的“已接受启动”只代表提交成功。主 Agent 的任务卡必须显示 Nest owner 的实际 taskId/attempt 状态，不得用 Host 自己的 task completed 覆盖 Nest 的 running/paused/unknown。

主 Agent 不逐目标重新派发已经由 Nest Root 领取的工作；Nest 不再反过来创建主 Agent 会话去继续相同任务。网络和模型费用都由实际执行 owner 记账，界面汇总只读，不创建第二份额度。

### 1. 从主 Agent 发起

用户说“检查这些已授权资产”，Agent 先读取当前项目和真实记录，生成一个有明确目标、能力、执行范围和费用限制的任务。已保存授权在原范围复用；只有真正新增的目标/权限/费用决策才集中确认一次。

Agent 给出任务卡：状态、当前动作、目标进度、真实费用、证据入口、暂停/继续。用户无须先理解 Root、mailbox、worker slice 或七种主管动作。

### 2. 从 Nest 查看和继续

Nest 默认展示“执行概览”，保留“结果与证据”“任务与成本”。当前项目内切换任务，默认展示结论与下一步；协作消息、原始错误、身份材料、兼容指令按需展开。

“交给 Agent 分析”携带项目、任务编号和尝试快照，打开统一对话的只读草稿。只传受校验编号，不传目标链接、Cookie、完整日志或本地路径；Agent 用 owner 工具重新读取当前状态，不能相信界面快照就是现在状态。

第一阶段不会伪称已建立持久的 taskId ↔ conversationId 绑定。重复分析仍可能创建独立草稿会话；第二阶段要实现可复用、可追溯的绑定与一键返回原任务。

### 3. 用户补充方向

主 Agent 将要求拆成：只读解释、原范围内的执行关注点、任务控制、范围/权限变化。解释直接回答；执行关注点进入同一任务的持久指令；暂停/恢复走原 owner；范围变化进入一次汇总确认。

“Agent 已收到”“已入队”“已送达”“已执行”“已验证”分别来自不同回执。不能靠流式文字把它们合并。重启只对账，不静默重放收费模型或目标写操作。

## 分阶段 Goal 与验收

每次只启动一个阶段 Goal，不把整套重构装进一个无限任务。

### 阶段 1：统一入口与执行工作台（本夜实施）

Goal 文本：审计当前 Agent/Nest 通道，交付分阶段规划；把 Nest 默认调查对话改为执行概览，以项目和 taskId 绑定的只读草稿接通主 Agent，折叠执行记录、身份材料和旧指令兼容入口，改善窗口适配，保留全部历史和运行任务。

验收：

1. shell 的本地与 Host catalog 标签一致，保存的 `dialog` 路由 ID 保留兼容，不新增第二套任务表。
2. Nest 按钮 → Board → Workspace → Shell → 主 Agent 草稿的整条事件链接通；不自动发送或启动。
3. 拒绝跨项目、无任务、异常任务编号和失效组件的交接；切换项目不会把旧请求灌入新对话。
4. 主对话已有回复运行时，草稿等待，不抢占会话；旧草稿保存。
5. 任务选择可展开，执行记录与身份材料默认收起；真正待确认草案和费用未知等阻塞不被藏掉。
6. 原暂停、恢复、人工裁决及分页读取回归继续通过。第一阶段不改冻结策略和底层 Worker。
7. 临时数据 UI 测试、编译及真实项目只读任务编号核对有证据；没做原生目标执行就明确未做。
8. App 替换必须通过正常暂停/落盘边界，不能中断正在跑的种子核验。发布只包含本阶段经过审查的路径。

### 阶段 2：双向任务绑定与方向修改

Goal 文本：实现 conversationId ↔ desktop projectId/Host projectId/taskId/attempt 的持久绑定；主 Agent 可读取、提出、应用并查询同一 Nest 任务的执行关注点，事件回流到原会话。

验收：schema 明确、幂等 operationId、原尝试/范围校验、未知结果先对账；真正的方向修改有模型/Worker 送达证据。跨会话和 A→B→A 晚回包负例通过；Source/Greybox 等不支持的动作明确降级。完成后移除普通用户可见的旧指令输入框，历史草案与收据保留。

### 阶段 3：计划与能力准入

Goal 文本：让主 Agent 与 Nest 共用执行能力目录，按目标任务实际需要生成可执行计划；一次展示缺模型、缺工具、缺授权、预算和依赖阻断。

验收：不可用角色不进入规划；未检查不伪装就绪；缺可选浏览器能力不误挡纯 HTTP 工作；真正依赖浏览器/上传/并发的任务不能“成功空跑”。全放开权限也不能凭空增加不存在的执行器。

### 阶段 4：证据回流与结果闭环

Goal 文本：统一任务/尝试/目标/工具结果/工件/候选/Reviewer 引用，主 Agent 可完整分页读取并定位原始证据，结果卡与 Nest 对应一致。

验收：原文保留、披露最小化、破损/超限/缺文件明确；空页有游标继续；报告和会话文件可定位；只有实际裁决能发布漏洞，不把侦察完成当验证完成。

### 阶段 5：恢复与资源治理

Goal 文本：统一停止、暂停中、已暂停、可恢复、请求未知、需对账和已结束的展示与控制；消除 UI 轮询和长事务卡顿。

验收：真实任务暂停→退出→启动→同 attempt 继续；原账本和剩余额度守恒；未知外部请求零自动重放；有可继续目标时不会误报全完成；压力下及时响应、无重复 loader/SQL 全表扫描。

### 阶段 6：补齐执行能力

Goal 文本：按实际业务收益逐个补齐受控浏览器、解析沙箱及所需专家，每个执行器有独立准入、证据、取消和故障回收。

验收：真实正负目标 + 进程/网络/内存隔离实测，不能以 mock HTTP 回放冒充浏览器。上传和并发测试仅在单独明确授权的测试环境验证。未完成者继续 unavailable。

### 阶段 7：清理重复配置与发布

Goal 文本：统一主模型、Nest 冻结策略、原生/Node 页面和实际可用执行能力的设置入口，移除重复普通面板，保留旧数据兼容。

验收：设置变更影响新任务，原任务冻结值不漂移；历史数据和源材料不覆盖；main、App、内置组件有可比对回执；云端 CI 和真实项目验证分开报告。凭据明文保留的既有修改必须独立完成披露边界审查。

## 默认界面与反馈

- 主色蓝：新建/主 Agent/明确下一步；灰色：读取、日志、展开；橙色：需处理的阻塞；红色：停止失败/破坏操作；绿色：有事实回执的完成。
- 状态变化即时反馈，刷新显示进行中、成功或失败，不制造“点击没有反应”。
- 默认只展示当前阶段与下一动作，完整技术记录保留在展开区域；真正阻塞不折叠到找不到。
- 窄窗先去掉常驻任务侧栏和辅助上下文栏，改成单列；任务编号、URL 和错误允许换行/滚动，按钮不挤占主要证据。
