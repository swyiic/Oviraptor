# 1.1.90 公开暴露面与 Agent 联动

内置 Assets 1.2.12。正常入口保留“总览、采集任务、线索复核”，数据源、内容簇、整改、事件、覆盖和配置收进“更多工具”。开始被动采集是主操作；录入与导出是辅助操作。

## 少操作的主流程

1. 在项目的公开暴露面开始一次被动采集，沿用已保存的来源、范围、归属/授权和请求预算。历史结果保留，不能将本轮上限内的结果称为全部覆盖。
2. 点“AI 梳理 · 前往对话”，或在线索行点“AI 分析”。打开新对话并填好只读草稿，发送后由 Agent 读取当前项目台账；页面不直接把证据、凭据或来源 URL 复制给模型。
3. Agent 可以分页读取线索元数据、定位单条线索、结合关联资产的 origin 与库存查询安排复核优先级。详情提供当前分类处置及冲突标记，已排除公开材料不能再当作高风险；自由输入的原始标题可能夹带密钥，改用类别标题。未提供原始证据正文、密钥、URL 用户信息/路径/查询串；缺少材料时应指明证据面板需要核对什么，不能编造证据。
4. 明确要求开始、恢复或停止暴露面任务时，Agent 提交一次控制，再读取一次实际状态并汇报。任务继续在后台执行，用户可到“采集任务”查看。暂停聊天不等于停止后台任务，取消采集接收回执也不等于已经停止。
5. 复核、确认/驳回、整改结论仍走原有版本化界面，不由模型自动写入；不会试用发现的凭据。

## 权限与成本

- 原有 `inventory.exposure.read` 继续只提供汇总和任务状态，不因更新而获得线索详情或采集执行权限。
- 新增 `inventory.exposure.details.read`：读取有界、脱敏的线索元数据。
- 新增 `inventory.exposure.run`：明确启动、恢复或停止被动采集。保存范围与实际归属授权门禁仍然生效，不允许模型修改配置或扩大范围。
- 已保存的授权和“完全放开”快照保持不变。新权限类别首次使用可能要求一次确认；不会将已有汇总授权静默扩张为联网执行授权，也不会为每条线索重复申请。
- 读取台账不触发外部采集。Agent 分析按当前模型计费；明确采集按项目现有来源和请求预算执行。本入口不调用 Hunter，也不改变 VPN。

## 可靠性修复

首次打开总览不再自动翻最多 20 页、读取 2,000 条准入资产；只有打开录入表单时才加载关联资产选择器。并发刷新复用同一快照读取。数据源失败不会被成功读取的汇总擦掉；切换任务不会使加载状态无法结束；切换项目立即清空旧快照和未提交表单，晚到的启动/保存/分级结果不显示到新项目。

租约过期且没有近期工作项活动的旧任务会显示冻结计划恢复入口；读取进度不改任务状态。恢复仍活跃任务只返回原任务，不再启动第二个执行器。

任务控制按 operationId 持久登记。相同已完成操作返回原回执；结果未知不会重放。状态工具支持按原 operationId 核对；缺少回执不能证明没有执行。原生层再次核对项目和任务归属，分页游标绑定项目、查询类型与筛选条件，撤销授权后的晚到响应会被 Host 拒绝。

## 验证边界

回归覆盖实际 Provider 循环、AppManager 权限/项目绑定、原生临时 SQLite、原页面组件和分页/竞争条件。云端增加暴露面和暴露面 owner 回归。已安装 App 的真实项目验证与最终 CI 状态记录在本次本地交付报告中。

临时库和本地 HTTP 夹具不等于真实互联网采集验收。模型相关性建议不等于已确认泄露；历史计数、证据存在和源站当前可达分别说明，不承诺百分之百识别或全面覆盖。
