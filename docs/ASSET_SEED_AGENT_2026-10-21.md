# 资产发现 Agent 与项目种子提炼（1.1.69）

## 修复的实际问题

旧自主探测每轮预览都从资产游标 0 开始。模型省略 cursor 时执行默认第一页，下一轮被动作去重拦住；如果首批资产都在确认范围外，还会得到 `items=[]`、`hasMore=true`。现在在 SQL 分页前筛选候选范围，最终仍按解析后的真实主机名严格核验。程序分别维护 inventory / harvest 游标，在成功回执后推进，不依赖模型回填游标。范围外资产、伪后缀和其他项目不会混入探测清单。

Hunter 的 `hunterEnabled` 是独立执行开关；`hunterRequests=0` 表示不限制精确查询数，不代表零积分或未启用。每轮模型上下文明确包含能力说明，结果面板显示启动时权限，历史运行不会被当前勾选状态改写。关闭开关后，即使旧数据带非零请求上限也不得调用 Hunter。精确证据校验和逐页积分回执保持有效。

日志保留机制会在首行返回 `id=0, stage=retention, level=info` 的清理提示。前端原先把它当作损坏数据，拒绝整个日志快照。现在仅接受该明确的提示行，仍拒绝普通 id=0、逆序错误和非法快照，读取失败保留上次内容。

## AI 提炼与人工确认

在「新建查询 → 域名线索与补查 → AI 提炼项目种子」可输入相关单位或域名关键词，也可留空先让模型帮助确认目标。

1. 后台只读遍历当前项目的全部非回收资产，包括仍关联在项目中的内容隔离资产。提取实际主机、已有证书 CN/SAN、指纹和已保存的页面 / CNAME 字段。不建立网络连接，不修改资产或范围。
2. 关键词只匹配已保存的单位、证书主体 Organization 或观察到的域名。ISP、ASN、证书颁发者、页面正文中的公司名不作为单位匹配依据。匹配结果仅代表相关候选，不能证明归属。
3. 返回前 80 个有来源的候选供人工查看，并保留总资产数、候选总数、资产 ID 示例与单位分布。聊天草稿按 UTF-8 长度进一步限量，明确显示实际交给模型的候选数；不会声称模型已经分析全部资产。数量过多时缩小关键词重新提炼。
4. 自动跳转到新的独立聊天并填入只读分析话术；原聊天未发送草稿保留。用户按发送后才会交给当前模型，授权沿用原有聊天机制。
5. 聊天上方的「核对候选并确认范围」返回候选面板。勾选具体域名，并明确确认域名及子域与目标单位相关，才保存范围。后端重新读取候选和原有范围，拒绝过期范围、伪造候选、跨项目确认。
6. 确认只保存发现范围，不修改正式归属结论，也不启动 Hunter 或探测。证书指纹、同一张证书的域名、混合证书和共享 CNAME 仍通过各自证据准入校验。

同一资产观察到的域名和指纹可能来自不同证书，不能把共现当成同证书关联。确认界面与模型话术都保留这一限制。候选报告及未发送草稿在当前应用会话中保留，关闭后可重新提炼。

## 入口整理

移除资产模块顶部的重复搜索框，保留资产列表自身的完整查询条件。操作日志保留左侧入口，移除顶部模块栏目中的重复入口。种子确认面板返回后自动定位，聊天提示条与内容纵向排列；候选复选框固定尺寸，避免被通用输入框样式撑满整行。草稿初次显示从分析话术开头开始。

## 验证边界

- Rust 聚焦回归：11 项自主探测测试，包含本地 HTTP 模型网关连续两页（模型省略游标）、空页游标推进、跨项目 / 伪后缀排除、未授权 Hunter 拒绝；2 项种子只读分析与人工确认测试。数据库均为临时测试库。
- 实际 Vue 组件聚焦回归：144 通过、1 项既有跳过；覆盖无自动发送 / 查询、显式确认、项目切换竞态、旧草稿保留、连续新请求、日志保留提示、导航入口。合成 IPC 和本地网关不代表外部服务验收。
- 正式 App 已使用真实项目复测本地摘要、跳转草稿、候选返回、原生复选框布局和日志读取；安装后的 121 个文件与构建包哈希一致，内置 Host 的 103 个文件通过校验。配置、资产与历史保留；Worker 心跳更新时间、Host 注册版本以及测试创建的空分析会话分别记录在本地交付凭据中，真实数据不提交仓库。
- 不以合成测试证明外部模型规划质量、Hunter 可达性、积分扣费或目标归属。VPN 保持原配置，远端失败及未知扣费不得自动重放。
