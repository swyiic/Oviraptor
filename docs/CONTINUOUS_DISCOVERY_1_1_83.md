# 资产持续发现闭环 · 1.1.83

## 使用流程

在项目的“AI 发现资产”填写明确目标单位；空项目直接点击“开始采集与 AI 发现”，可补充 FOFA 初始公司或域名。已有项目默认复用本地记录，不重新采集；需要追加 FOFA 时再明确选择重新采集。

流程由后台持久任务接续，而非前端模拟点击：

1. **FOFA 被动首采**：只采集候选，不因查询命中就认领或主动探测全部结果。
2. **证据核验**：本地去重整理，AI 分类；不足的证据自动进入公开研究，明确第三方不进入付费种子，真正矛盾的集中复核。
3. **免费发现**：未确认候选可从固定公共 CT 来源读取公开证书；已确认范围自动执行 CT、DNS/CNAME 和 TLS 补证。新证据回流，新增范围按域名家族一次确认。
4. **Hunter 精确补查**：只有此运行明确开启后，才按真实证书 SHA-256、已确认域名或已观察具体 CNAME 查询并自动翻页。允许使用免费和权益积分，页面及累计费用可见。
5. **去重回流**：沿原资产导入与来源记录合并，再分析新增证据；本轮收敛后保留状态，等待新证据，不反复消费相同已完成查询。

资产页与聊天使用同一个执行状态。暂停保留原任务、种子、公开证据、模型响应和 Hunter 分页回执，继续沿原断点；不会因为恢复重建相同付费请求。

## 证据之间的分工

- CN/SAN 是证书上的名称；只从实际叶证书读取，供应商 `cert.domain` 关联名单不冒充 SAN。
- SHA-256 是具体 DER 的身份，关联同一张证书，不独立证明企业归属。公共 CT 预证书不作为最终叶指纹送入 Hunter。
- Subject Organization 需要与输入法定名称、已确认单位目录或有来源的受控关系匹配，不使用“移动/中移”等子串直接认领企业。
- CNAME 是具体解析关系，共享 CDN/云平台不因被指向而整体进入范围。
- 备案主体只约束对应端点，不传播到同机、同组或其他根域。

AI 的置信度不能产生“百分百归属”。当前叶证书身份、逐域备案、官方单位关系和明确反证形成可追溯建议；新增执行范围由用户集中确认。缺证不等于无关，也不要求逐条人工确认。

官方单位关系研究目前内置中国移动官方投资者概览的精确受控关系，保存正文摘要、来源和核验时间，并有缓存期限；不会从页面里的关联企业、参股银行或客户名单推断所有子公司。其他单位继续使用输入法定名称及已确认目录。来源不可访问或正文变化时保留详细错误，不编造查证结论。

## 恢复、费用与权限

- 首采 intent、原生 run 和服务 owner 同事务绑定。原种子在发布前持久落盘，并记录 SHA-256；首次执行和恢复都校验摘要，不采用后来编辑的项目目标。
- 同一请求只返回原任务；项目、目标、任务类型或 owner 不匹配时拒绝接续。后台不自动重放被中断的 FOFA 请求，明确继续操作才恢复原任务。
- 免费补证有持久队列、租约、限速、退避和迟到回执保护。公共来源只联系固定 crt.sh；未确认候选不会被主动连接。
- Hunter 每页重新核验当前范围和来源。结果或扣费未知时保留原回执并停止自动重发；本地去重不能退还平台已经对重复结果扣除的积分。
- 相同指纹只规划一次，域名树覆盖重复子域查询。不同精确种子仍可能返回重叠资产，因此费用与实际新增记录分开显示。
- 聊天模型不能自行打开首采或 Hunter；新执行选项经会话、人机确认和当前权限核验。旧“完全放开”仅对校验过的受信内置资产组件做窄兼容，保留原授权记录；不会扩展其他新权限。
- 暂停只控制此流程记录的任务，不按“最新任务”猜测并停止其他手动操作。

## 验证记录

验证及安装结果在最终交付时补充。代码回归、公开网络测试、真实项目测试与外部平台索引覆盖分别记录，不互相替代。

## 实际限制

CT、DNS 和现有证据可以找到尚未被测绘平台收录的资产，但不能保证发现从未出现在任何公开记录、证书或解析线索中的主机。Hunter 查询正确也不保证平台已收录该证书；应保留零结果、错误响应和请求时间，用后续新证据继续发现。

不修改 VPN。原资产、历史、配置、人工判断及原始模型/付费回执保留；AI 整理不直接删除、恢复隔离资产或扩大执行范围。
