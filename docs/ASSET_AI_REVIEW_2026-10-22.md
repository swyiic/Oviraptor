# 本地资产 AI 批量审阅与主动探测边界（1.1.72）

## 这一轮发现的问题

1. 旧的“AI 提炼”虽然遍历本地资产，交给对话的只是 80 项候选中的限长摘要；不能代表 AI 审过全部证书。新版增加持久的全量整理和分批模型审阅，旧入口折叠为单次摘要讨论。
2. `assets.company` 是采集标签，FOFA/Hunter 查询目标都可能写进这里。不能把“中国移动”标签当成备案或证书主体。新版区分采集标签、提供商明确的备案单位、同一张叶证书 DER 的 Subject Organization，以及尚未绑定证书身份的单位提示；颁发者 Organization 不作归属证据。
3. 主动探测的资产数、时长和模型决策次数原来混在发现流程里，到达限制还显示为“结束”，容易误解为全项目覆盖。新版将本地审阅、测绘采集、主动探测分为三个页签；达到限制记为 `limited`，分页未读完就停止记为 `needs_review`。
4. 同一批目标换个组合可能重复提交主动探测。新版按实际资产 ID 保留本轮提交记录，重叠目标不会再次访问或再次计入提交数。
5. “包含隔离区”的识别必须覆盖回收、人工拒绝、内容隔离和自定义页面规则；不能只看软删除标记。新版统一这些来源，只读审阅，不恢复或删除历史资产。
6. 真实聊天诊断发现，Agent 能读正常资产数量，却读不到新建查询保存的确认范围。补充现有 `inventory_stats.discoverySeeds` 的 `confirmedScope` / `seedReview` 只读上下文，随每次镜像读取刷新；无需增加工具或权限，不授予模型确认范围的能力。

## 使用路径

资产 → 新建查询 → **AI 整理与范围确认**：

1. 填写明确单位，例如“中国移动集团及其下属单位”，也可以限定某个子公司或业务。
2. 点击“整理全量本地证据”。不联网、不调用模型、不耗测绘积分；按 250 条分页扫描，保存游标；以当前最大资产 ID 固定本次上界。后续新入库的资产需重新整理。
3. 按叶证书 SHA-256 身份、未绑定指纹的证书名称、实际观察域名所属域名组去重。每组保留关联资产引用及计数，避免每个端口、每个 URL 都请求一次 AI。
4. 可先“试审一批”，核对真实结果，再“继续 AI 全量审阅”。模型每批最多 12 组，按字节进一步缩小，逐批保存意见与 Token 用量；可暂停、重启后手动继续，不受主动探测的 100 条 / 15 分钟限制。
5. 查看“建议关联”“待人工核验”“建议排除”。认可关联只保存审核意见；勾选实际观察域名，再明确确认，才会增加范围。不会因 AI 建议自动授权、恢复隔离资产或扣 Hunter 积分。
6. 主动探测与 Hunter 仍在各自入口启动。单位名称不是域名授权，域名组的父域标签也不自动成为授权根域。共享服务必须限定具体租户。单次确认最多 50 项，总确认范围最多 500 项。

## CN、Organization、CNAME、SHA-256 如何配合

- **SHA-256**：完整叶证书 DER 的身份，不是公钥、序列号、PEM 文本或证书链的哈希。精确相同证书才能合并证书身份。
- **SAN / CN**：名称与具体指纹绑定。同一张原始证书的 SAN 优先；没有名称时，批量审阅可读取这张证书的 CN 作为候选。提供商历史证书不能借用当前 TLS 证书的名称。
- **Subject Organization**：只从匹配该指纹的叶证书 DER 读取；缺失就显示未取得，不从颁发者、查询标签或另一张证书补全。
- **CNAME / 主机域名**：本地观察线索。指向共享 CDN、云平台或同一个 IP 不代表整个云平台都属于目标单位。
- **AI**：结合明确单位与上述证据给关联建议。共享 / 混合 SAN、未绑定指纹、截断证据、低模型自评分均归人工核验。AI 自评分不是资产归属概率，也不构成付费检索准入。
- **Hunter**：继续使用原有同证书范围与排除规则校验。确认一个主机并不能使该主机上的无关证书自动合格。精确指纹查询、域名查询、CNAME 查询是不同关系，结果仍需核验；这一轮未改为模糊单位大范围查询。

## 限制和费用的实际含义

| 操作 | 资产数 / 时长 | 费用 / 停止条件 |
| --- | --- | --- |
| 整理本地证据 | 本项目当前上界内所有记录，含所选隔离来源 | 不联网；可暂停和按游标继续 |
| AI 批量审阅 | 处理去重后的证据组，不受主动探测的轮数、资产数、时长限制 | 当前模型输入/输出 Token；逐批保存。未知请求不自动重放 |
| 主动探测最多资产 | 本轮实际提交访问的资产数；失败请求也可能占用提交名额 | 不限制 Hunter 返回多少记录，不代表项目总资产上限 |
| 主动探测时长 | 本轮规划、等待和执行的时间；到时停止后续动作并等待当前请求退出 | Hunter 可能因此暂停，已保存页码可在其补查入口继续 |
| AI 决策次数 | 本轮自主探测的规划调用次数 | 达到次数显示“达到停止条件”，不声称覆盖完成 |
| Hunter 精确补查 | 近 30 天、所有可用分页，仍受服务端额度和准入条件限制 | 可使用免费与权益积分；显示分页与消耗，未知扣费不自动重发 |

模型发送内容限定为域名、指纹和有限的单位/来源摘要；不发送 API Key、页面正文或完整证书。单组发往模型的证据限制 6KB，批次证据约 16KB；示例截断会强制人工核对。完整资产引用仍保存在本地，因此“分组去重审阅”不等于模型逐字读过每一条原始资产。预计批次数仅是近似值。

请求前先落库标记本批已发送；中断、响应丢失、JSON 不完整、编号缺失/重复/凭空生成，都不会自动重新购买同一次分析。已返回用量据实保存；无法确认的调用显示计费未知。继续时跳过未知批次，留在人工队列。接收方端点或凭据变化后，不能把旧任务自动发送给新接收方，须重新整理新任务。

## 仍需后续打磨

- 这次是资产发现和审阅这一条能力闭环，不代表通用聊天 Agent、扫描规划、故障恢复全部达到其他成熟 Agent 的水平。
- 新的批量审阅由资产页面发起和控制；聊天 Agent 通过现有 inventory_stats 读取保存范围与审阅计数摘要，尚无专用的批量审阅启动/暂停工具，也不会自行把 AI 建议确认成范围。旧的单次摘要聊天入口仍保留。
- 真实聊天仍偏字段化，跨模块统计口径尚未直接给出映射解释；需要继续打磨短结论与证据展开，而不是只追加更长提示词。
- 老审阅任务仍保存在数据库，目前页面默认展示最新任务；多任务历史浏览和审核结论复用需要继续完善。
- 域名跨品牌、外包系统、自签证书、过期证书和共享证书不能靠单位名自动证明所有权；无法取得足够证据的记录必须保留为待核验。
- 真实 Hunter 网络与积分回执应由用户关闭 VPN 后复测。本轮不修改 VPN，不用受控测试冒充线上联通。
