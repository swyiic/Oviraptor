# 自动补证与持续发现（1.1.77）

## 用户可见行为

「资产 → 新建查询 → 自动补证与持续发现」是一个持久任务入口。确认范围保存后，一次启动即可按同一队列运行：

1. 整理项目内已观察的范围内主机和本地证书。已有完整叶证书但缺 SHA-256 时先解析本地 DER，不用证书名称代替指纹。
2. 向 crt.sh 查询确认根域下的 CT 名称，处理完整返回列表，去重；通配符作为证据保存，不当作已存在的具体主机。
3. 对新发现的范围内名称查询 DNS A、AAAA、CNAME。保存外部 CNAME 关系，禁止沿该关系扩大探测范围。
4. 优先使用本次公开 DNS 地址连接原主机名的 TLS/SNI，读取叶证书，计算完整 DER 的 SHA-256。拒绝私网、Tailscale CGNAT、VPN 假 IP 等非公开地址。只握手，不请求页面。
5. 保存范围内 SAN 新名称并继续队列；新增 HTTPS 候选保持待核验。证书变化追加历史观察，不覆盖原始页面、人工归属、隔离或回收状态。
6. 新证书回填已有审阅任务：旧未绑定证书名称有实际叶证书承接后自动更新证据。已完成模型回执、人工认可/排除不会被重新分流覆盖。

持续模式默认每小时检查 CT/DNS/新资产，TLS 最短每日复查。可以选 15 分钟、1 小时、6 小时、24 小时，线程并发 1/2/4/8。单轮模式处理当前队列后停止，错误单列。运行任务在重启后自动继续；手动暂停的任务保持暂停。

此任务不调用 Hunter，也不为每条证据调用模型。付费查询仍走原有当次证据与范围准入、请求去重、分页及积分记录；不将 CN、Organization、CNAME 和 SHA-256 拆成无条件付费查询。

## 冲突和错误的区别

- 证书不覆盖请求主机：按叶证书 SHA-256 汇总主机，显示为身份冲突；不依据该证书自动扩大范围或调用 Hunter。
- HTTP 403、429、超时、DNS 服务失败：保存阶段、目标、具体错误和退避记录，不视为资产不存在，不变成人工逐条审核。
- 范围改变或项目关闭：停止任务并拒绝旧范围写回。排除规则在领取和结果提交时再次检查。
- 「已阅」只保存已读决定，不授予新范围、归属或恢复权限；同一指纹增加冲突主机时重新进入待阅。

近期界面最多预览 20 组冲突及每组 8 个主机，完整主机集和全部执行日志保存在数据库。CT 单次响应上限 16 MiB；超限显式失败并记录，不截取前 1000 条冒充完整结果。CT 只覆盖服务收录的公开证书，不能保证枚举所有未公开或无证书的资产。

## 执行入口和持久状态

- UI IPC：`enrichment_action`。
- 对话 Agent：`discovery_enrichment_start/status/pause/resume`，由可信 Host 绑定当前项目，通过带私密 bearer 的 loopback bridge 调用同一原生执行器，不交给 Worker。
- 原生自主探测：`enrich` 动作接共享队列，单轮免费补证；返回任务 ID 后应报告后台进度。共享任务独立于当前模型规划轮次，暂停/恢复入口在新建查询。
- 权限沿用 `certificate.collect` 控制执行，`inventory.read` 控制进度读取，未新增通用网络或 shell 权限。
- `asset_enrichment_runs/items`：范围快照、队列、游标、进程持有、重试时间；同项目只允许一个 enabled 任务。
- `asset_enrichment_observations/events/conflicts`：去重内容观察、逐次回执、按身份汇总的冲突。

所有新增表均追加创建。配置、API Key、VPN、历史任务和原始页面不迁移、不重置。

## 验证边界

自动化验证和真实 App 结果分别记录；测试数据不作为生产发现证据。真实项目仅使用当时已保存的确认范围，AI 候选与人工「认可关联」不会自动变成探测范围。

Google DoH JSON 的请求与响应校验依据 [Google 官方文档](https://developers.google.com/speed/public-dns/docs/doh/json)：分别查询 A/AAAA、验证原问题、拒绝截断响应，DNS 错误码与空答案分别处理。保留现有业务网络设置，不修改系统代理或 VPN。
