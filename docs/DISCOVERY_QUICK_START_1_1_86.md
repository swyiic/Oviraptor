# 发现资产 · 简化操作说明

日常只使用“资产 → 发现资产”。

1. 新项目填写目标单位，点击“开始采集与发现”；系统先采集 FOFA，再接续核验与扩展。
2. 已有项目点击“继续增量发现”或“从断点继续”，复用现有数据、任务和逐项结果。
3. 只有新增范围需要确认。页面先展示域名家族及具体边界，点击“确认所选范围并继续”即作出本次明确确认，无需再勾一遍授权。
4. 点击“查看资产”查看结果。无需逐项整理线索、补证或切换多个控制面板。

## 默认页面

目标、一个主操作、项目历史记录/本轮新增/需决定三项概览及实际 Hunter 费用。已保存目标收为摘要，可点“修改”。暂停和失败原因优先显示，状态读失败时只提供重试读取，不盲目启动。

“发现设置”包含自定义 FOFA 种子、重采选项及隔离/回收记录分析。“过程与用量”包含详细进度、模型请求、证据和诊断。普通补证由主流程接续，任务中心的手动证书补采默认收起。

## Hunter 和确认范围

- Hunter 仍需明确启用，不因简化界面自动打开；使用已核验的精确线索，实际费用持续展示。
- 本地显示“已保存账户”仅表示 Key 存在，不表示网络或账号实测通过。未配置时可前往资产 API 设置，返回后保留同项目目标草稿。
- 原 Hunter 请求或扣费未知时，可明确点击“继续免费发现”。旧费用与原回执保留，未知付费请求不会重发。
- 新增范围仍以本次展示的 token、原范围、具体主机及当前选择校验。轮询、切换会话或修改选择后，旧按钮不能确认未经展示的新范围。
- 缺证线索属于自动补证队列；真正冲突才集中审核。排队与正在执行分别说明，不把历史种子数量当作已确认资产数量。
- 归档项目可读历史，不提供启动、确认或其他写操作。

## 少数手动需求

“更多操作”可选择自定义 FOFA 采集、确认范围管理、单条 CT/DNS/Hunter 查询、本地线索维护、独立探测或补证工具。选中哪种才挂载哪种，主面板与草稿保持。手动 FOFA 创建的是独立任务，页面显示任务编号和查看入口，不宣称已自动接管为 AI 协调任务。

“项目种子与历史”用于回查来源、首次/最近轮次、关联资产、分页及费用回执。升级前首次轮次未知的记录仍保持未知。

## 验证边界

交互通过编译后的生产组件回归，覆盖首次/已有项目、单次确认、陈旧按钮、读失败、归档、配置往返、收费未知时免费继续、项目切换和懒加载。真实项目的只读数据用于宽窄窗口组件渲染检查；该检查不替代安装版业务 API 验证，也不代表实际操作过原生窗口。安装替换保留配置和数据，VPN 不作调整，外部 Hunter 付费网络不纳入本轮实测。
