## 需你定夺（本次不盲改的三项）及理由

### 1. db::open 连接池（约 712 处调用）
`db::open` 每次返回**自有** `Connection`，调用点"打开→用→丢弃"。要透明池化就得把返回类型换成池句柄，波及全部 712 处；且 rusqlite 连接非 `Sync`、SQLite 写串行、代码注释已记录过"界面像卡死"的锁事件。在薄测试网下、且本机无法对你的真实应用做并发压测，机械改 712 处到有界池有**死锁/池耗尽进而卡死应用**的高风险。
- 建议：单独、专门地做，先上并发压测与泄漏检测，再逐步迁移；不适合夹在长会话里赶。

### 2. 模型传输共享 runtime
`transport.rs` 每个请求**自建** current-thread runtime 且**靠 drop 来取消**连接（drop runtime = 关 socket）；client 也按请求的 proxy/超时/重定向逐次构建。reqwest 的连接池绑定在被每次丢弃的 runtime 上，所以**连接复用在当前架构下本就不可能**，与共享 runtime/client 互斥。要共享就得把取消模型从"丢 runtime"改成显式 abort —— 架构级改动、并发风险实在，而对**偶发**的 LLM 流式请求收益很小。
- 建议：维持现状（清晰取消优先于连接复用）；若将来要高频调用再做取消模型重构。

### 3. 凭据明文 → 系统钥匙串
无 `keyring`/`security-framework` 依赖，需新增**跨平台 OS 依赖**（各平台后端不同、macOS 首次访问会弹系统授权框——行为变化）。凭据（`api_key`/`access_token`）不仅 Rust 读，Node agent-host 与 LLM 代理也要用。附加式迁移须：写时存钥匙串+库里留引用、读时优先钥匙串回退明文、懒迁移、钥匙串不可用时优雅降级，且**不能破坏多进程取凭据**。这些必须用**你的真实密钥/环境**端到端验证，并对真实库做回读测试——本次都做不到。半成品迁移可能让应用读不到凭据→所有扫描/模型调用失败，**把你锁在自己的密钥外**，爆炸半径大。
- 建议：作为单独任务，带真实凭据流端到端验证 + 隔离库回读测试再上；先决定是否接受 keyring 依赖与 macOS 授权框。
