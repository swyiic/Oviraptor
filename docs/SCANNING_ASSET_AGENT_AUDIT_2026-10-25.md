## 1. 结论

当前有两条需要分别修复的工作流：

1. **资产 → Agent → 种子清洗**：用户明确要求处理整个中国移动项目，Agent 却停在统计和整体拒绝，要求用户逐条人工处理。当前已经存在种子分页读取、详情和 UI 域名排除能力，但工具披露、清洗执行和归属证据仍未组成完整工作流。
2. **资产 → 扫描 → 证据回流 → 恢复**：存在结果重复脱敏引起的收据一致性缺陷，普通恢复与专用费用接续通道不一致，以及浏览器/部分沙箱/专家能力缺口。

修复的产品目标是：**用户明确目标和清洗意图后，系统自动读取全量、归并证据、补充查证、处理有充分依据的无关项；人工只集中处理真正有冲突或高影响的决定。** 不能把“没有达到绝对确定”直接转成“全部拒绝”或几万条人工任务。

历史的“CI 通过”“框架已有”“某个任务 completed”均不能替代对应业务链路验收。

### 3.5 应实现的使用流程

用户只需明确一次目标，例如“中国移动集团及其下属单位”，再要求清理明确无关种子。系统应自动接续：

1. 读取整个项目的种子与证据，分页直到末尾，保存快照/水位与游标；不能只分析首页或聊天摘要。
2. 按域名家族、同一张证书 SHA-256、独立单位证据归并，避免对每个主机重复调用模型；共享平台按租户/具体主机保留边界。
3. 复用已有人工排除、有效公开证据和历史判断；只对缺证或证据过期的组补查。
4. 按需要查询公开的官网、备案/注册主体、单位关系等；保存来源、查询时间、证据摘要、证据 ID 和判断理由。联网查公开资料与主动探测某台目标是不同操作，不能把目标探测范围机械套成“禁止查证任何外部主体”。
5. 对具备充分且无冲突证据的无关种子，按用户已授权的清洗意图执行**可撤销的批量排除**；默认不物理删除资产、证据或历史。
6. 对缺证项自动继续补证；失败项记录重试状态；真正互相矛盾或涉及已确认自有资产的项目集中列给用户处理。
7. 统一输出：本轮读取/归并/查证数量、自动排除数量、保留数量、待补证数量、冲突数量，以及撤销本批次入口。

新增授权范围、不可逆删除等另按实际影响处理；不应把每条普通可恢复排除都拆成一个人工确认。

### 3.6 判断要求

- 不承诺 AI 能证明一个资产“永远百分之百不属于某集团”。产品需要的是**有来源、可复核、可撤销的当前项目种子相关性判断**。
- 明确第三方单位、独立域名和公开主体信息相互支持，且没有自有域名/独立证书等冲突证据的，才能进入自动排除集合。
- 不能只按域名关键词、CN、Organization、CNAME、IP/ASN 或云厂商标签的单一命中/不命中作最终归属判断。
- 中国移动提供云/网络服务，不等于租户资产属于中国移动；某资产使用外部云，也不等于它不属于中国移动。
- 证书 SHA-256 证明同一张证书，不证明所有部署或同证书 SAN 都属于同一单位。CA 颁发者不是证书持有者。
- 新增范围建议、人工归属确认、线索相关性排除、资产回收是四种不同动作，不能混写成一个状态。
- AI confidence 是辅助排序，不能代替证据门槛；用户要求高确定性不能成为全盘拒绝可执行工作的理由。

### 3.7 防止 Hunter 继续浪费积分

- 清洗动作必须在付费查询计划生成之前生效；已排除项不得进入新的 Hunter 请求。
- 排除域名时联动检查其关联证书、CNAME 等；若指纹仅由这些被排除证据支持，应停止其补查。
- 共享指纹仍有独立有效的目标单位证据时，保留该支持关系，不能连带错误排除。
- 排除会影响尚未发送的队列；已经发出的或结果未知的请求只能对账，不能假称已取消或退分。
- 只恢复本批排除，不等于重新发送历史 Hunter 请求；恢复应重新核对证据与当前队列。

### 3.8 必须补齐的验收

- 用户原句能让模型看到并使用种子分页/详情工具；确实读完全部页，不以统计代替全量读取。
- 简单计数、组合归属问题、明确批量清洗三类意图分别有回归，不互相提前收口。
- 全量任务可暂停、退出 App 后恢复；不能重复分析已保存组或重发未知网络请求。
- 多域名批次有快照/摘要版本绑定、幂等 operation ID、影响预览、执行回执、审计和整批撤销。
- 跨项目排除拒绝；并发修改导致版本不符时重新计算，不能使用旧预览覆盖新判断。
- 共享证书、云租户、外部云自有业务、历史证书、混合 SAN、证据过期、联网失败均有正反例。
- 自动排除后，种子列表、AI 提炼、CT/DNS/TLS 补证、Hunter 计划都使用一致的排除结果。
- 原始资产、原证据和历史记录保留；恢复后状态与证据关联可对账。
- UI 只保留“开始清理/暂停/继续、进度、冲突汇总、查看排除结果、撤销本批”等必要操作；不要求翻几十页逐条点确认。

## 4. 扫描链路的七项问题

### S1 · P0：重复脱敏破坏已保存结果与交付收据的一致性

**证据：当前源码 + 上轮局部最小复现 + 历史同类错误。**

- [specialist/receipt.rs](../src-tauri/src/agent_runtime/multi_agent/specialist/receipt.rs#L187) 首次保存结果时会脱敏。
- [readonly_assessment.rs](../src-tauri/src/commands/multi_agent/readonly_assessment.rs#L122) 交付时再次 `redact_json`。
- [saved_message.rs](../src-tauri/src/agent_runtime/multi_agent/mailbox/saved_message.rs#L136) 要求 summary 与保存收据逐字一致。
- [readonly_assessment.rs](../src-tauri/src/commands/multi_agent/readonly_assessment.rs#L245) 暂停恢复时再次比较文本、用量及拒绝状态。

当前脱敏函数对某些 authToken、session、cookie 样例不幂等：已有脱敏标记会被再次改写。上轮三个纯本地样例均复现变化。该问题可触发 `mailbox_saved_result_mismatch` / `readonly_assessment_receipt_mismatch`。

这证明局部代码缺陷；**不证明每一条历史扫描都由它导致**。不能通过跳过收据校验、取消脱敏或伪造相等结果修复。

验收：一次/重复脱敏保持稳定；已付费保存结果重复交付与暂停恢复一致；真实篡改、跨任务、使用量不符仍被拒绝；不重复调用模型填补已保存结果。

### S2 · P0：聊天普通恢复与专用费用接续没有组成统一流程

**证据：当前源码确认；不应描述成“所有付费任务都没有恢复功能”。**

[普通恢复费用门禁](../src-tauri/src/commands/native_web_resume_finance.rs#L43) 发现模型/工具/目标请求等执行历史后，最终会拒绝普通接续；已结算历史也不能通过普通接口获得新额度。聊天预检会说明这一点。

项目已有[专用费用核对与接续 API/UI](../src/features/sentinel/reconciliation/api.ts#L7)。缺口是：用户从聊天恢复时，没有直接完成“识别阻断原因 → 进入原 owner 的核对/剩余额度接续 → 回到同一任务”的统一体验。

验收：保留原账本、消耗、未知费用和额度；沿专用流程恢复，不创建一个全新额度伪装继续；已完成结果不重放；用户不必理解多套 owner/账本入口。

### S3 · P1：真实浏览器与部分沙箱能力未就绪

**证据：当前源码确认，限制范围必须说清。**

- [agent_tools_browser.rs](../src-tauri/src/commands/agent_tools_browser.rs#L142)：有 `run_budget` 的多 Agent、或注册单 Agent 会拒绝真实浏览器执行，原因是所有浏览器网络请求尚未纳入 Broker。单 URL HTTP 降级不能证明点击、登录 DOM、XHR、WebSocket 的行为。
- [macos_static_parser.rs](../src-tauri/src/tool_supply/sandbox/macos_static_parser.rs#L22)：此处 macOS 离线 static parser 因硬内存隔离未验证而拒绝，不等于所有 OS/容器沙箱都不存在。
- 另有容器解析适配器，安装工具/批准工具包不等于执行器就绪；需要独立验证资源、文件和网络边界。

验收：浏览器跳转、子资源、XHR/WebSocket 都经过相同授权范围约束；CPU/内存/文件/网络隔离有真实正反例；能力不可用时在规划前说明，不把 HTTP 回放冒充浏览器验证。

### S4 · P1：上传、并发竞态专家仍未实现

[child_contract.rs](../src-tauri/src/agent_runtime/multi_agent/scheduler/child_contract.rs#L58) 和 [coordinator_stub_role_gate.rs](../src-tauri/src/commands/agent_native/coordinator_stub_role_gate.rs#L26) 对对应角色返回 `upload_role_not_implemented` / `concurrency_role_not_implemented`。

验收：能力目录、模型可选动作和 UI 同步禁用未实现能力；不能先消耗规划调用再发现执行器不存在。完成实现后需独立真实执行与证据审核验收，不能以存在角色枚举代替。

### S5 · P1：聊天扫描预检不是完整执行预检

[scan_preflight](../src-tauri/src/scanning/agent_channel.rs#L119) 只解析保存模型与费用历史，显式返回 `networkTested: false`、`engineAdmissionValidated: false`。

验收：输出统一就绪清单，分别核对模型、项目/目标授权、工具、Broker、浏览器、沙箱、费用与恢复条件。未实际检查的项目明确“未检查”，不可用项提前阻断并给可执行原因，不让用户启动后才发现缺能力。

### S6 · P1：源码工作台默认预算与后端能力冲突

[AgentWorkbench.vue](../src/features/sentinel/components/AgentWorkbench.vue#L41) 默认 `code`，美元预算默认 5；[useWorkbenchTaskCreation.ts](../src/features/sentinel/workbench/useWorkbenchTaskCreation.ts#L97) 对非 Web 且带美元预算的任务直接拒绝，后端也没有对应美元费用账本。

验收：代码审计/灰盒/CI 的默认值应符合真实能力；默认可用流程不要求用户猜测要清空隐藏字段。若美元硬上限未实现，必须准确展示 token/时间等已执行限制，不能假称已限制美元账单。

### S7 · P1：聊天执行错误被泛化，诊断信息不足

[scanning/agent_channel.rs](../src-tauri/src/scanning/agent_channel.rs#L367) 在调用引擎的 start/pause/resume 返回 `Err(_)` 时，统一映射为 uncertain，丢弃原稳定错误码；[状态投影](../src-tauri/src/scanning/agent_channel.rs#L74) 又缺少足够的失败阶段/脱敏原因。

这不是说所有校验错误都会被吞掉：该调用之前的参数、授权、费用门禁仍可能返回具体错误。

验收：区分确定未启动的拒绝、已提交、已执行、结果未知和持久化失败；保留脱敏稳定错误码、阶段、task/attempt/operation 关联。Agent 应能直接诊断，不让用户反复去任务中心截屏；未知结果仍不得自动重发。

## 6. 其他已知联动风险

上轮真实 AI 复核曾把 HTTP/HTTPS 合计响应误称为 HTTPS，并把全部观察称为页面；后续补过字段语义提示，但**模型叙述仍不能充当统计验收**。

另一次模型把合法工具别名拼错，在执行前被归为 `host_tool_permission_denied`；当时真实授权没有丢失，其他只读台账工具正常。这说明还需区分“未知工具名/工具未披露/真实权限缺失”，不能所有情况都引导用户再次授权。

这两个已知案例不能直接认定为本次种子清洗拒绝的唯一原因，应分别保留回执与回归。

## 7. 实施优先级与交付顺序

| 阶段 | 范围 | 必需产出 |
| --- | --- | --- |
| A · 用户当前工作流 | 修复种子工具披露、计数口径与全量分页 | 原用户问法能够真实读取种子和证据，不再误报工具不存在 |
| B · 全量可恢复清洗 | 接多域名证据分析、补证、批量排除/撤销、Hunter 队列过滤 | 用户一次明确目标后自动接续；人工只处理真实冲突 |
| C · 扫描 P0 | 修复收据脱敏一致性、普通恢复到专用费用接续的联动 | 保存结果不重复付费，暂停/重启后账本和证据可接续 |
| D · 运行就绪与诊断 | 完整预检、默认表单、准确错误分类 | 开始前知道是否可执行；失败后能定位实际阶段 |
| E · 能力补齐 | 浏览器 Broker、相关沙箱、上传/并发专家 | 分能力真实验收，不用框架测试替代生产执行 |

A/B 与 C 可以隔离并行，但不能把所有分支混在一个没有验收出口的大 Goal 中。每阶段必须有最小失败复现、最小修复、回归和真实项目验证。

## 8. 统一回归与真实验收标准

### 自动回归

- 原用户中文请求的计数、分析、批量排除意图覆盖；工具过滤后清单符合需要和实际权限。
- 两项目交叉、旧会话响应迟到、索引/项目切换、分页中断、数据水位变化的反例。
- 排除预览过期、部分执行失败、重复提交、撤销、共享证书保护和任务恢复。
- 收据脱敏幂等、交付重复、篡改拒绝、费用/请求未知不重放。
- 默认工作台可用；未实现角色/环境在预检中明确显示。
- UI 统计来自结构化台账；模型不得自造字段含义、把范围确认当单位归属。

### 真实项目

1. 先备份并记录配置、原资产、原种子、历史、原权限与当前任务状态。
2. 在中国移动项目确认一致的计数口径；全量读取、分析与分组，不限本页。
3. 实际产生带证据和批次回执的排除结果，验证不会进入新 Hunter 请求；按可恢复方式验证撤销。
4. 中途暂停、退出 App、重新打开后恢复原任务；验证游标、原证据、计费及已处理项不被重置。
5. 扫描另选明确授权的验收目标；验证真正执行与证据回流，不把公开页面 200 或侦察完成当漏洞验证。
6. 对照备份核对配置、资产与历史保留；只有任务产生的预期增量/明确授权状态变化可以不同。
7. 对照当前 App、内置组件与 main 的实际代码/资源，并分别报告本地回归、云端 CI、真实行为和剩余限制。

## 本轮实施边界（1.1.95 / Assets 1.2.17 / Scanning 1.4.1）

- Agent 种子 list/detail 工具进入实际只读工具集合；组合统计问题不会在总量后提前收口。全项目清洗由持久化 owner 分页整理全部 raw、ledger 及附加来源引用，不把数万行塞给模型。
- 新增 `discovery_cleanup_start/status/pause/resume/restore`，统一 Native owner 和项目种子页面。独立 `inventory.seed.cleanup` 权限披露模型费用、公开查询和可撤销排除；兼容升级保留旧授权，不把新类别偷偷加入旧授权。
- 本地事实、固定公开 CT/叶证书、DNS/CNAME 与官方单位关系补证分开保存。AI 按有用证据批量判断并保存理由及用量；无响应、无命中、403、运营商和 CA 不构成无关证据。未知模型请求不重放，暂停后收到的结果仅保存，恢复时在本地消费原回执。
- 自动排除须有域名对应的公开证书事实与域名对应主体的交叉核对，且覆盖整个候选族、无目标支持、混合证书、共享平台或快照变更。缺证继续自动补查，冲突集中展示；不删除资产或种子，不改变探测范围，不启动 FOFA/Hunter。
- 原始索引条目、规范台账种子、证据组分别计数。排除批次记录原事件，撤销不覆盖后续人工决定。Hunter 与免费补证在发送前重新检查排除和独立支持；已发送但扣费未知的请求不重发。
- 扫描收据重复脱敏改为幂等，保留内容、用量、任务及 child 绑定和篡改校验。新增真实 localhost transport 到交付，以及暂停、重开数据库后消费一次的回归。
- `scan_recovery` 给出原任务账本、费用核对状态及明确错误阶段；确定未启动与未知执行结果分开。沿用现有严格合同接通同一 attempt 从未派发的恢复。

**未完成的扫描执行缺口仍保留：** 已产生费用的目标剩余工作不能通过普通 resume 重启；新 Root 费用评估只重评冻结证据，不是继续目标执行。不能移除门禁、重置额度或另建任务冒充恢复。S3 的真实浏览器 Broker、S4 的未实现专家等亦不能因本轮回归通过而算完成。

本地验证：界面 2,094 项中 2,086 通过、8 项原有跳过；Agent/SDK/应用 1,055 项中 1,036 通过、19 项原有跳过；资产 Native 243 通过、5 项需专用外部/历史样本的原有忽略。新增清洗真实 localhost 模型、暂停/冷恢复、未知请求防重放，以及排除发送边界、旧项目兼容回归已纳入。真实项目与安装验证应以本次独立交付回执为准，不把这些本地测试等同于外网归属准确率或整体扫描验收。

真实历史数据兼容补充：项目的 `icp` 字符串主要是备案号，不当作单位名。对本域证书 CN/SAN 绑定的 Subject Organization，可先由 AI 分析并补取当前公开叶证书交叉核对；仅有供应商关联域名、来源公司标签或本地 O 不自动排除。CT/DNS 按实际已观察主机名排队，通配符记录单独处理，不把通配符当作裸根域或多层子域的 TLS 覆盖证明。

公开服务拒绝、限流或网络故障按任务和服务持久化退避，后续新入队名称也遵守，重启后不失效；最近错误与下次重试时间可展开查看。多个独立主体按主机保留集合，不能因覆盖其中一个而误排除。目标单位的供应商证书 CN/SAN 主体线索虽然不能直接确认归属，仍会阻止自动排除并进入补证。

付费历史扫描续跑的剩余工作：需要独立的目标续接 consumer，绑定原 scan/attempt、Root/assignment、剩余目标及多维余额，以续接收据连接新执行 fence；不能修改原 exit、重置原截止时间、覆盖终态 branch，不能重发 sent/unknown 请求。已过原截止时间的历史扫描还需要明确的延时合同。当前版本只交付从未派发任务的恢复、已保存付费 publication 的本地消费回流与准确的恢复诊断，不能将其称为已闭合所有扫描恢复。

真实项目验收补充修复：启动话术中的“可撤销批量排除”“支持暂停恢复”是能力描述，不再误识别为立即撤销/暂停；现有授权足够时不会要求用户重复放开权限。离线真实备份重放还发现旧审阅记录被重新分流覆盖，现已保护原人工决定及无当前自动化版本的模型终态整行记录，仍允许新版派生状态接收补证后自动分流。原失败断言保留，并补齐对应正反例。


## 持续真实运行发现的性能修复（1.1.96）

1.1.95 在中国移动真实项目已整理 188,016 条来源记录、保存 16 次模型结果后，持续运行暴露出来源变更核验的性能缺陷。线程采样定位到快照反关联查询：缺少按任务、主机、来源及来源引用查找的覆盖索引，导致反复扫描大快照，不能以“状态可读”认定后台持续可用。

1.1.96 为快照补充 `(run_id, host, source, source_ref)` 索引；旧启用任务由执行 owner 在接管前自动迁移，不要求重建任务或重新提交模型请求。状态读取不执行 DDL。回归使用同一生产 SQL 的万条快照，检查查询计划、虚拟机步数和主机/来源/引用变更仍能触发原安全门槛。真实项目还需以原任务继续推进、旧回执不重放及数据保留校验验收。

实际公开 CT 请求还出现 HTTP 502；502/503/504 纳入持久化服务退避，后续新入队任务也遵守。外部查询失败继续保留缺证和详细错误，不能据此自动判定无关或伪造排除成功。此处不修改 VPN，也不以其他目标的模拟证据写入真实项目。
