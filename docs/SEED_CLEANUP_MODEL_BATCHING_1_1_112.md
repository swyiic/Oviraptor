# 种子核验模型批次收敛（1.1.112）

## 实际问题

真实项目的同一域名组有 2–7 次不同证据版本的模型记录。没有发现相同 group_key / basis_hash 的重复请求；但每次只有部分 TLS 或官网信息新增，尚不足以改变原生判断，仍会再次调用模型。原谓词只检查“证据有变化且含主体线索”，没有等待同组的有限补证结束。

## 行为调整

- 原生校验已经具备完整、独立、覆盖全部保存名称且没有目标证据或主体冲突的排除依据时，立即进入 AI 审阅，无须等待冗余来源。
- 其他组等待本组 pending / retry / running 来源全部结束后，再对最后的证据版本审阅。其他组仍有任务不会阻塞本组。
- 有新的证据后仍可再审；相同 basis 和未知收费请求均不重发，已有请求、用量和响应原文不改写。
- 已确认范围和强目标证据仍先由本地原生分类保留；人工决定、原始种子、资产、排除撤销和授权规则保持原行为。
- 这只改变付费分类的时机，不缩短补证次数、不把请求失败判无关，也不暂停整个核验。有限补证和最终缺口归档继续由原任务推进。

## 验证边界

回归覆盖连续部分证据不发模型、本组 retry / running 不能误判完成、其他未完成组不阻塞已完成组、完整独立证据仍可立即审阅、最终模型只发送一次、未知请求不重放和 151 组本地分类全部可达。

旧实现下新增用例实际失败（模型候选 2，预期 0）；修复后资产发现完整回归 401 项通过、0 失败、7 项显式快照或外网检查未运行；安装保护 79 项通过。真实项目新谓词只读查询使用 asset_cleanup_research_group 覆盖索引，约 33ms，不新增表或迁移，不重置来源预算。

真实全量核验的结束数量与案例以任务终态报告为准；本说明不表示全量已结束。安装时沿用正常暂停、完整模型回执落盘、数据库与 App 备份、正常退出、签名包替换及原任务恢复边界；配置数据保留，VPN 不动。
