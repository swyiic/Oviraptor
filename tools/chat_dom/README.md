在仓库根目录运行 `npm run test:chat-dom`，浏览器打开 `http://127.0.0.1:1439`。仅监听回环地址，按 Ctrl+C 关闭。需要已有的项目依赖，不安装新浏览器或下载工具。

这是人工验收夹具，不是会自动返回通过/失败的测试命令。它直接编译生产 `AgentDialog.vue` 及其聊天 composable；这些模块的 API 与事件导入由测试服务器替换，未被替换的 `@tauri-apps/` 导入明确报错。生产 Vite 配置与入口不引用夹具。模拟内容仅在内存中，刷新清空；草案、审批、补证与执行方法明确拒绝，不调用 Tauri、模型或目标。任务/阅读偏好也是模拟存储，不能证明真实数据库持久化。

服务器入口可供测试导入插件，但只有直接运行入口时才监听端口。`tools/test_agent_dialog_events.cjs` 已纳入 `npm run test:ui`，包含导入隔离和真实组件消费模拟状态的回归；不另外增加重复测试命令。状态快照、增量追读和历史接口每次均最多 100 条；增量有更多消息时返回当前窗口水位及 `timelineHasMore`，不是一次返回全部积压消息。

## 操作与预期

1. **事件突发**：记录初始读取数，开启延迟，点击 A 突发 200 条。在途数应为 1，读取只增加 1。再次点击 A 突发 200 条，读取不再增加。关闭延迟并释放最早请求，后续按最多 100 条的窗口继续追读，最终水位达到 401、近期缓存 300 条；初始水位 1 的 400 条新增消息共需四个增量窗口，不能再要求“最多补读 1 次”。畸形通知不增加读取或浏览器错误。
2. **有界展示**：401 条模拟消息中，近期缓存只保留最后 300 条、当前页最多 100 个气泡；初始显示序号 302–401，不应把“300 条已加载”误认为历史总量。翻到 202–301 后新增 200 条，仍显示 202–301，转换为最多 100 条的独立阅读快照；更早一页继续读 102–201，最新一页返回 502–601。快照不具备服务端连续窗口证明，禁止直接标读并显示说明；翻页本身不写已读。快照复用唯一历史页槽位，不累积旧页载荷。
3. **切换与旧响应**：在 A 输入无敏感内容的草稿，开启延迟，注入 A 消息；选择 B。此时 A/B 各一个在途请求，总数可以为 2，这不违反同一视图事件读取单飞。先释放最新的 B，再释放旧 A，页面仍应只有 B 的消息。关闭延迟后回到 A，恢复 A 的未发送草稿。
4. **新 attempt**：A 已加载高 sequence 时点 A 新 attempt。应完整读取新 attempt 的第 1 条消息，不拼接旧 attempt；页面总数重置为 1。
5. **失败重读**：开启延迟，点下次读取失败，再点 A 突发。释放最早请求，页面显示读取错误；约 3 秒后产生一个被延迟的轮询读取。关闭延迟、释放该请求，错误消失且消息补齐。终态任务恢复后回到约 15 秒的低频核对，不应维持快速错误循环。
6. **卸载**：开启延迟并注入事件后卸载组件；释放旧请求，不能重新显示组件或抛异常。重新挂载后从模拟存储读取，不复用旧视图的发布权。
